# LolzCloud cloud service

Комнаты на `https://lolzcloud.com`, проверенный вход Lolzteam и общий серверный источник Spicy Lyrics. Node.js 24 LTS, без npm-зависимостей. Код сервиса входит в открытые исходники; реальные ключи и сессии не входят.

## Развёртывание

1. Создать OAuth-приложение Lolzteam: сайт `https://lolzcloud.com`, Redirect URI `https://lolzcloud.com/auth/lolz/callback`, права `basic read`. Публичный Client ID сохранить в `LOLZ_CLIENT_ID`.
2. Отдельного системного пользователя `lolzcloud` использовать без интерактивного входа. Код поместить в `/opt/lolzcloud-server/current`; Node 24 — в `/opt/lolzcloud-runtime/node`. Каталог состояния `/var/lib/lolzcloud` принадлежит этому пользователю, права `0700`.
3. Заполнить `/etc/lolzcloud/credentials.env` по `.env.example`: владелец root, права `0600`, каталог `0700`. `SPICY_LYRICS_SECRET_KEY` — серверный ключ своего приложения, только на сервере. Он никогда не отправляется клиенту. Без него комнаты работают, общий источник текста недоступен.
4. Установить `ops/lolzcloud.service` в systemd, выполнить `systemctl daemon-reload` и `systemctl enable --now lolzcloud`. Сервис слушает только `127.0.0.1:4387`.
5. В HTTPS-блок Nginx своего домена подключить `ops/nginx-proxy.conf`, проверить `nginx -t`, затем перезагрузить Nginx. HTTPS обязателен: cookies используют `Secure`, `HttpOnly`, `SameSite=Lax` и префикс `__Host-`. В Cloudflare использовать Full (strict), обход кэша для `/api/*`, `/auth/*`, `/room/*`, `/cloud/*`, `/login`, `/rooms`, `/connect`.
6. Проверить `/api/health`, вход через форум и подключение приложения. Для другого домена изменить origin в сервере и клиенте, OAuth Redirect URI и Nginx согласованно.

`LOLZ_REDIRECT_MODE` принимает только `explicit` (по умолчанию) или `registered`. В режиме `explicit` запрос авторизации передаёт `redirect_uri=https://lolzcloud.com/auth/lolz/callback`. Опциональный режим `registered` опускает только этот параметр и оставляет выбор единственного зарегистрированного callback провайдеру; в настройках OAuth-приложения должен быть ровно один полный адрес `https://lolzcloud.com/auth/lolz/callback`. Такой выбор предусмотрен [OAuth 2.0 §3.1.2.3](https://www.rfc-editor.org/rfc/rfc6749#section-3.1.2.3) и [upstream-контроллером bdApi](https://github.com/bshaffer/oauth2-server-php/blob/5a0c8000d4763b276919e2106f54eddda6bc50fa/src/OAuth2/Controller/AuthorizeController.php#L217-L252); поддержку конкретной версией форума нужно проверить при входе. Режим не отключает регистрацию callback, одноразовый `state`, cookie браузера или проверку личности через `/users/me`. Неизвестное значение останавливает запуск сервиса.

## Доступ и хранение

Lolzteam использует implicit OAuth: токен приходит во fragment. Callback сразу убирает fragment из адреса, отправляет токен собственному HTTPS-серверу и проверяет пользователя через `/users/me`. Переданный клиентом ник или ID не определяет личность. OAuth state одноразовый и привязан к cookie браузера. Токен форума после проверки не сохраняется. Сервер хранит только хеши собственных сессий сроком до семи дней и публичный профиль. Logout отзывает собственную сессию.

Для приложения используется отдельное подключение: код в браузере нужно сверить и подтвердить, затем приложение получает свою зашифрованную локально сессию. Гости комнат тоже входят через Lolzteam. Управление музыкой и закрытие комнаты доступны только ведущему. Участники отображаются по подтверждённым профилям; несколько вкладок одного пользователя не создают дубликаты. Приватное прослушивание не передаёт сведения о треке.

Комнаты и коды подключения находятся в памяти и закрываются при перезапуске сервиса. Отсутствующий ведущий останавливает трансляцию состояния через 20 секунд; отсутствующие гости исчезают через 25 секунд. Нет голосового чата или серверной передачи аудио: каждый гость слушает официальный SoundCloud Widget, его доступность зависит от самого трека и региона. Браузер может потребовать одно нажатие для воспроизведения. Изменение скорости ведущим не поддерживается Widget, поэтому для комнат лучше обычная скорость.

Spicy запрашивается только вошедшими пользователями, с лимитами и суточным кэшем. Сохраняются сведения об источнике и авторах синхронизации. Экспорта исходного текста нет. Требуется Spotify track ID той же записи; при отсутствии точного совпадения пользователь может указать ссылку Spotify. Остальные источники текста продолжают работать без ключа Spicy.

Тесты из корня репозитория: `node --test tests/cloud.test.cjs`. Используются изолированные локальные fixtures; в рабочем сервисе нет тестового входа или обхода проверки аккаунта.
