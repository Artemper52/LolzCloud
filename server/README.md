# LolzCloud cloud service

Комнаты, социальные профили, друзья и приглашения на `https://lolzcloud.com`, проверенный вход Lolzteam и общий серверный источник Spicy Lyrics. Node.js 24 LTS, без npm-зависимостей. Код сервиса входит в открытые исходники; реальные ключи и сессии не входят.

## Развёртывание

1. Создать OAuth-приложение Lolzteam: сайт `https://lolzcloud.com`, Redirect URI `https://lolzcloud.com/auth/lolz/callback`, права `basic read`. Публичный Client ID сохранить в `LOLZ_CLIENT_ID`.
2. Отдельного системного пользователя `lolzcloud` использовать без интерактивного входа. Код поместить в `/opt/lolzcloud-server/current`; Node 24 — в `/opt/lolzcloud-runtime/node`. Каталог состояния `/var/lib/lolzcloud` принадлежит этому пользователю, права `0700`.
3. Заполнить `/etc/lolzcloud/credentials.env` по `.env.example`: владелец root, права `0600`, каталог `0700`. `SPICY_LYRICS_SECRET_KEY` — серверный ключ своего приложения, только на сервере. Он никогда не отправляется клиенту. Без него комнаты работают, общий источник текста недоступен.
4. Установить `ops/lolzcloud.service` в systemd, выполнить `systemctl daemon-reload` и `systemctl enable --now lolzcloud`. Сервис слушает только `127.0.0.1:4387`.
5. В HTTPS-блок Nginx своего домена подключить `ops/nginx-proxy.conf`, проверить `nginx -t`, затем перезагрузить Nginx. HTTPS обязателен: cookies используют `Secure`, `HttpOnly`, `SameSite=Lax` и префикс `__Host-`. В Cloudflare использовать Full (strict), обход кэша для `/api/*`, `/auth/*`, `/room/*`, `/cloud/*`, `/login`, `/rooms`, `/connect`, `/social`.
6. Проверить `/api/health`, вход через форум и подключение приложения. Для другого домена изменить origin в сервере и клиенте, OAuth Redirect URI и Nginx согласованно.

`LOLZ_REDIRECT_MODE` принимает только `explicit` (по умолчанию) или `registered`. В режиме `explicit` запрос авторизации передаёт `redirect_uri=https://lolzcloud.com/auth/lolz/callback`. Опциональный режим `registered` опускает только этот параметр и оставляет выбор единственного зарегистрированного callback провайдеру; в настройках OAuth-приложения должен быть ровно один полный адрес `https://lolzcloud.com/auth/lolz/callback`. Такой выбор предусмотрен [OAuth 2.0 §3.1.2.3](https://www.rfc-editor.org/rfc/rfc6749#section-3.1.2.3) и [upstream-контроллером bdApi](https://github.com/bshaffer/oauth2-server-php/blob/5a0c8000d4763b276919e2106f54eddda6bc50fa/src/OAuth2/Controller/AuthorizeController.php#L217-L252); поддержку конкретной версией форума нужно проверить при входе. Режим не отключает регистрацию callback, одноразовый `state`, cookie браузера или проверку личности через `/users/me`. Неизвестное значение останавливает запуск сервиса.

## Доступ и хранение

Lolzteam использует implicit OAuth: токен приходит во fragment. Callback сразу убирает fragment из адреса, отправляет токен собственному HTTPS-серверу и проверяет пользователя через `/users/me`. Переданный клиентом ник или ID не определяет личность. OAuth state одноразовый и привязан к cookie браузера. Токен форума после проверки не сохраняется. Сервер хранит только хеши собственных сессий сроком до семи дней и публичный профиль. Logout отзывает собственную сессию.

Для приложения используется отдельное подключение: код в браузере нужно сверить и подтвердить, затем приложение получает свою зашифрованную локально сессию. Гости комнат тоже входят через Lolzteam. Управление музыкой и закрытие комнаты доступны только ведущему. Участники отображаются по подтверждённым профилям; несколько вкладок одного пользователя не создают дубликаты. Приватное прослушивание не передаёт сведения о треке.

Протокол комнат 2 поддерживает одного активного ведущего в приложении или браузере. Управление защищено арендой на 15 секунд, номером обновления и идентификатором соединения; старый ведущий не может перезаписать нового. Владелец передаёт пульт и назначает DJ. Без действующей аренды воспроизведение приостанавливается; отсутствующие гости исчезают через 25 секунд.

Настройки, очередь и последняя позиция комнат сохраняются в `rooms-state.json` и восстанавливаются на паузе, без действующей аренды. Коды подключения и пульты телефона не восстанавливаются. Чат и реакции временные. Каждый гость слушает официальный SoundCloud Widget; доступность зависит от трека и региона. Браузеру может потребоваться нажатие Play. Общая скорость строго 1×. Локальные файлы и звуковые эффекты ведущего другим участникам не передаются.

Состояния доставляются через SSE `/api/rooms/:id/events`, часы калибруются через `/api/clock`, а при обрыве работает повторное подключение и HTTP-опрос. Для SSE нужны `proxy_buffering off` и длинный `proxy_read_timeout`; `/remote/*` тоже направляется в сервис. Сервер ограничивает обычные JSON-запросы 16 КБ, зашифрованную копию плеера примерно 1 МБ, social media JSON с base64 — 1,4 МБ; Nginx допускает 1500 КБ.

## Профили, друзья и приглашения

`/social` — общий интерфейс для Android, ПК и браузера. `/api/social/me`, `/api/social/users`, `/api/social/friends`, `/api/social/invitations` и `/api/social/notifications` требуют проверенной сессии; изменения дополнительно проверяют Origin и CSRF. `/api/social/events` доставляет уведомления через SSE. Чтение уведомления не принимает приглашение. Приглашение действительно час и при принятии повторно проверяет комнату, доступ и бан.

Идентичность, оригинальный аватар и титулы берутся из подтверждённого ответа Lolzteam `users/me`. Титулы используют `user_groups` и `curator_titles`, а не редактируемый `custom_title`. Имя, группы и ранг нельзя назначить через PUT профиля. Для старых сессий без групп нужен повторный вход. Ранг «Слушатель+» отделён от титулов: `LOLZCLOUD_PLUS_USER_IDS` предназначен для серверного включения, по умолчанию пуст; платёжная система пока не реализована.

В каталоге состояния сохраняются `social-state.json` и `profile-media/`. Их нужно резервировать вместе с `sessions.json`, `rooms-state.json` и `player-profiles.json`, сохраняя закрытый доступ к резервным копиям. CSRF сохраняется вместе с сессией, чтобы перезапуск не ломал открытые клиенты. Социальный профиль не является зашифрованной копией музыкальных настроек `/api/profile`.

Аватары и фоны загружаются только как PNG/JPEG с проверкой содержимого и размеров. `/media/profiles/` раздаёт публичные изображения по хешированным именам без токенов сессии в URL. Отменённые, неиспользуемые загрузки очищаются в пределах пользовательской квоты; текущие аватар и фон сохраняются.

Проверенное развёртывание с резервной копией и rollback выполняет `tools/deploy-social.cjs`; SSH alias задаётся через `LOLZCLOUD_DEPLOY_SSH_HOST`. Результаты текущего выпуска и ограничения клиентов описаны в [аудите 0.9.13](../docs/mobile-parity-0.9.13.md).

Пульт телефона требует того же проверенного аккаунта, поддерживает только команды плеера и отключается через 90 секунд без обновления компьютера. Приватное прослушивание скрывает метаданные. Облачные копии в `player-profiles.json` содержат только зашифрованный клиентом AES-GCM конверт; пароль серверу не передаётся. Номер ревизии защищает от перезаписи копии другим устройством. Резервируй эти файлы вместе с `sessions.json` в закрытом каталоге.

Spicy запрашивается только вошедшими пользователями, с лимитами и суточным кэшем. Сохраняются сведения об источнике и авторах синхронизации. Экспорта исходного текста нет. Требуется Spotify track ID той же записи; при отсутствии точного совпадения пользователь может указать ссылку Spotify. Остальные источники текста продолжают работать без ключа Spicy.

Тесты из корня репозитория: `npm test` и `npm run test:rooms`. Во втором сценарии работают несколько скрытых клиентов, настоящий HTTP/SSE и детерминированная имитация Widget. Это проверка протокола и коррекции позиции, а не гарантия задержки реального SoundCloud. В рабочем сервисе нет тестового входа или обхода проверки аккаунта.
