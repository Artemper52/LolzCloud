# Нативный музыкальный каталог

Отдельный сервис `lolzcloud-music`, независимый от Telegram и входа Lolzteam. Android получает поисковые результаты и воспроизводит MP3 своей MediaPlayer/MediaSession: музыка не открывается в браузере.

- `GET /music/search?q=<artist title or canonical SoundCloud track URL>&offset=0` → `{tracks:[{id,url,title,artist,cover,duration,audioUrl}],nextOffset}`. До 20 записей на страницу, duration в секундах. Только публичные полные записи, без BLOCK/SNIP; до 20 минут.
- `/music/audio/<id>/<signature>.mp3` → проверенный полный MP3 128 кбит/с со встроенной обложкой. HEAD/range поддерживаются, URL подписан стабильным HMAC и не содержит секретов или cookies.
- `GET /music/prepare/<id>/<signature>` → сразу `202 {state:"preparing",retryAfterMs:1000}` либо `200 {state:"ready",audioUrl}`. Одна подготовка на ID для всех клиентов, bounded cache queue и не более 128 отслеживаемых задач; ошибка возвращается безопасным JSON 503 и кратко кэшируется. Native-плеер ждёт готовность отдельно от HTTP-загрузки MP3. Этот маршрут не добавляет возможностей обхода источника.
- `/music/health` → версия протокола и готовность.
- `POST /music/wave` → персональная партия до 20 записей с теми же подписанными `audioUrl`. Версия JSON — `1`; клиент передаёт лайки, историю, обратную связь, настройки, заблокированных исполнителей и отпечатки прослушанного за сутки. Используется тот же подбор, что на ПК: настроение, занятие, знакомое/новое, запрос словами и подтверждённый год записи. `utcOffsetMinutes` соответствует `Date.getTimezoneOffset()`. Поддерживаются `cursor`, текущий трек, отправная точка и `omit` для уже подготовленной очереди.

Волна принимает до 1 000 000 байт JSON, 2000 лайков/истории/реакций/отпечатков, 100 исполнителей, 8 недавних и 40 исключённых записей. Описание запроса — до 240 символов. Неизвестные поля и адреса вне публичных записей SoundCloud отклоняются; cookies, OAuth и клиентские аудиоссылки не нужны. Личные сигналы используются для одного запроса и не записываются на сервер. Ответы источника повторно проверяются перед выдачей подписанного URL: импортированная пара ID/URL не может подменить каталог. Подготовка MP3 начинается только при воспроизведении.

Ограничения волны: 20 запросов в минуту на IP, 8 одновременных запросов, общий бюджет обращений к провайдеру и 12-секундный срок подбора. Кэшируются только проверенные публичные метаданные и связанные записи; объём кэшей ограничен. Успешный ответ с пустым списком означает, что подходящие записи без повторов закончились; ошибка источника возвращается отдельно как безопасный JSON 503. Подбор не гарантирует неизменную доступность внешнего трека после выдачи.

Переиспользованы проверенные каталог, конвертер и кэш LolzCloud, с отдельными состоянием и процессом. Два конвертера, очередь до 20 заданий, кэш MP3 до 2 ГиБ и 5-минутный кэш запросов. Ошибки источника возвращаются как JSON с понятным повтором. Query история не записывается. Общий счётчик запросов ограничен по адресу прокси.

Процесс слушает только `127.0.0.1:4389`, пользователь `lolzcloud-music`. Ключ `/etc/lolzcloud-music/credentials.env` root:root0600; данные `/var/lib/lolzcloud-music`0700. Секрет не менять при обычном обновлении: он сохраняет валидность ссылок сохранённых треков. Секреты не входят в исходники, архивы кода и отчёты. Внешний SoundCloud OAuth-клиент и доступ к личным лайкам SoundCloud этим API не подменяются.

Каталог исключает записи с известными только защищёнными CBC/CTR-потоками и preview-длительностью вместо полной записи. Доступность провайдера может измениться между поиском и воспроизведением; отказ остаётся явным и допускает повтор. Уже подготовленный подписанный MP3 может обслуживаться из кэша без metadata/upstream, сохраняя привязку к точному ID.

Если каталог принимает прежнюю публичную конфигурацию SoundCloud, а получение потока возвращает 401/403, загрузчик один раз обновляет эту конфигурацию и повторно запрашивает ту же запись. Одновременные обновления используют один запрос. Повторный отказ сохраняется как ошибка; личная OAuth-сессия остаётся прежней, а временные ошибки сервера не запускают смену конфигурации.

Полнота готового MP3 проверяется декодированием его аудиодорожки в пустой выход. Общий `progress` конвертации с обложкой может завершиться временем картинки `0.04s`; это не длительность песни. Проверка сохраняет порог 80% для записей длиннее 20 секунд, общий срок подготовки 110 секунд и бюджет двух работников. Настоящий короткий preview удаляется, полный MP3 с обложкой остаётся доступен.
