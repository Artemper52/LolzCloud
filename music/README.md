# Нативный музыкальный каталог

Отдельный сервис `lolzcloud-music`, независимый от Telegram и входа Lolzteam. Android получает поисковые результаты и воспроизводит MP3 своей MediaPlayer/MediaSession: музыка не открывается в браузере.

- `GET /music/search?q=<artist title or canonical SoundCloud track URL>&offset=0` → `{tracks:[{id,url,title,artist,cover,duration,audioUrl}],nextOffset}`. До 20 записей на страницу, duration в секундах. Только публичные полные записи, без BLOCK/SNIP; до 20 минут.
- `/music/audio/<id>/<signature>.mp3` → проверенный полный MP3 128 кбит/с со встроенной обложкой. HEAD/range поддерживаются, URL подписан стабильным HMAC и не содержит секретов или cookies.
- `GET /music/prepare/<id>/<signature>` → сразу `202 {state:"preparing",retryAfterMs:1000}` либо `200 {state:"ready",audioUrl}`. Одна подготовка на ID для всех клиентов, bounded cache queue и не более 128 отслеживаемых задач; ошибка возвращается безопасным JSON 503 и кратко кэшируется. Native-плеер ждёт готовность отдельно от HTTP-загрузки MP3. Этот маршрут не добавляет возможностей обхода источника.
- `/music/health` → версия протокола и готовность.

Переиспользованы проверенные каталог, конвертер и кэш LolzCloud, с отдельными состоянием и процессом. Два конвертера, очередь до 20 заданий, кэш MP3 до 2 ГиБ и 5-минутный кэш запросов. Ошибки источника возвращаются как JSON с понятным повтором. Query история не записывается. Общий счётчик запросов ограничен по адресу прокси.

Процесс слушает только `127.0.0.1:4389`, пользователь `lolzcloud-music`. Ключ `/etc/lolzcloud-music/credentials.env` root:root0600; данные `/var/lib/lolzcloud-music`0700. Секрет не менять при обычном обновлении: он сохраняет валидность ссылок сохранённых треков. Секреты не входят в исходники, архивы кода и отчёты. Внешний SoundCloud OAuth-клиент и доступ к личным лайкам SoundCloud этим API не подменяются.

Каталог исключает записи с известными только защищёнными CBC/CTR-потоками и preview-длительностью вместо полной записи. Доступность провайдера может измениться между поиском и воспроизведением; отказ остаётся явным и допускает повтор. Уже подготовленный подписанный MP3 может обслуживаться из кэша без metadata/upstream, сохраняя привязку к точному ID.
