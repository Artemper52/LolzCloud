# LolzCloud Telegram

Отдельный Node.js сервис для `@lolzcloudbot`: inline-поиск музыки в любом обычном чате, поиск в личке, отправка музыкальным аудиофайлом и постоянный кэш. Он не получает переписку чатов и не требует добавлять бота в группу.

## Использование

В любом чате: `@lolzcloudbot тёмный принц гной`, затем выбрать результат. В личке — `/start`, название/исполнитель или полная HTTPS-ссылка на трек SoundCloud. Есть `/help`, `/search`, `/settings`, `/privacy`.

## Оформление

`/start` показывает фирменную карточку с короткой инструкцией и кнопками поиска, недавних песен и помощи. В личке каждый результат — карточка с обложкой, исполнителем, длительностью и позицией; кнопки «Назад»/«Далее» перелистывают то же сообщение. Следующая страница каталога подгружается по необходимости. «Отправить аудио» выделена зелёным, «В другой чат» возвращает в inline-поиск выбранной песни.

После отправки доступны «Ещё у артиста» и «В личку», а в личке — «Поделиться песней». Ошибка обложки подставляет бренд, сохраняя правильные название и действия. Двойное нажатие не создаёт две одновременные отправки. Карточки принадлежат создавшему их аккаунту и действуют 20 минут; поисковая фраза для перелистывания живёт только в памяти.

Исходник баннера — `telegram/assets/welcome.html`. `node tools/render-telegram-assets.cjs` рендерит JPG/PNG через Electron и копирует иконку проекта. Реальное оформление ограничено компонентами Telegram: используются HTML captions, native photo/audio, кнопки и поддерживаемый Telegram стиль `success`. Новая приветственная фотография переиспользует собственный `file_id`, привязанный к SHA-256 картинки.

В рабочей конфигурации включён режим обложек. Для него нужен Inline Feedback 100%; выбор результата превращает короткое сообщение загрузки в аудио. Начальный прямой audio-режим пользователь уже подтвердил действием в Telegram.

Источник — тот же публичный каталог SoundCloud, который используется в LolzCloud. Недоступные, заблокированные и preview-записи не выдаются. Собственного API-приложения SoundCloud и доступа к приватным библиотекам нет. Доступность зависит от источника и региона; реклама/подписка не обходятся. Полный поток преобразуется в MP3 128 кбит/с с Unicode ID3-тегами и обложкой. Обрезанный поток не выдаётся за песню.

## Два режима inline

- По умолчанию `TELEGRAM_INLINE_ARTICLES=0`: настоящий `InlineQueryResultAudio` с публичной подписанной MP3-ссылкой. Работает при любом Inline Feedback, включая 0%. На первом обращении Telegram забирает подготовленный файл с сервера. Для файлов с известным `file_id` сразу используется `InlineQueryResultCachedAudio`.
- `TELEGRAM_INLINE_ARTICLES=1`: холодные результаты показывают обложку, название, исполнителя и длительность как article; после выбора текст «Готовлю аудио…» заменяется музыкальным файлом через `editMessageMedia`. Для автоматической замены **нужен BotFather `/setinlinefeedback` = 100%**. Под сообщением остаётся кнопка повторной загрузки, если feedback не пришёл или источник отказал. Кэшированные Telegram-файлы отправляются сразу.

В прямом режиме для ещё не загруженного результата Bot API не предоставляет поле миниатюры в `InlineQueryResultAudio`; обложка встроена в MP3 и появится в отправленном файле. У cached audio обложка хранится в самом Telegram. [InlineQueryResultAudio](https://core.telegram.org/bots/api#inlinequeryresultaudio), [cached audio](https://core.telegram.org/bots/api#inlinequeryresultcachedaudio), [chosen feedback](https://core.telegram.org/bots/api#choseninlineresult).

## Кэш

1. Поиск: 5 минут, до 300 запросов в памяти, одинаковые параллельные запросы объединяются.
2. MP3: постоянный каталог `audio/`, по умолчанию 2 ГиБ с очисткой старых неиспользуемых файлов. Два конвертера, до 20 ожидающих работ; повторные загрузки одного трека объединены. Кэш переживает перезапуск. Незавершённые временные файлы удаляются. Известный Telegram `file_id` отправляется без обязательного наличия MP3 на диске.
3. Telegram `file_id`: автоматически сохраняется при отправке аудио в личку по запросу пользователя, в том числе по кнопке «В личку» у песни. По выбору пользователя используется серверный кэш без обязательного служебного канала. Если в будущем настроен `TELEGRAM_CACHE_CHAT`, выбранные песни дополнительно отправляются в **отдельный служебный канал**, где бот должен иметь право публикации. Один файл загружается туда один раз и затем отправляется через cached audio. В личные чаты пользователей служебные загрузки не отправляются.

В текущем режиме без канала: до 20 минут и 20 МБ, чтобы MP3 можно было получить по URL. С каналом и режимом `TELEGRAM_INLINE_ARTICLES=1`: до часа и 48 МБ через upload. Трек не обрезается ради лимита. Общие счётчики песен могут использоваться в пустом поиске; тексты запросов и личная история поиска не записываются на диск. `file_id` привязаны к конкретному боту.

## Сервер

Node.js 24, установленный `/usr/bin/ffmpeg`, отдельный пользователь `lolzcloud-telegram`, порт только `127.0.0.1:4388`. Публичный Nginx проксирует `/telegram/`; комнаты на 4387 продолжают работать отдельно. `GET /telegram/health` показывает состояние и давность успешного long polling. Аудио доступно по HMAC-подписанному URL без Telegram-токена. Поддерживаются HEAD и byte ranges. Сервис переиспользует SoundCloud-модули LolzCloud; вместе с ними упакован существующий `@xmldom/xmldom` с лицензией, без установки пакетов на сервере.

Секреты: `/etc/lolzcloud-telegram/credentials.env`, root:root 0600, каталог 0700. Состояние: `/var/lib/lolzcloud-telegram/telegram-state.json` и `audio/`, отдельный сервисный пользователь. Резервировать JSON и закрытую конфигурацию; MP3-кэш можно восстановить. При смене бота использовать новый каталог состояния.

Перед развёртыванием подготовить приватный JSON **вне репозитория**: `token`, стабильный случайный `mediaSecret` (64 hex), необязательные `cacheChat`, `inlineArticles` (boolean). Задать `LOLZCLOUD_TELEGRAM_CONFIG` и `LOLZCLOUD_DEPLOY_SSH_HOST`; выполнить `node tools/deploy-telegram.cjs --deploy`. Скрипт упаковывает только код и необходимые исходники, проверяет checksum, сохраняет серверную резервную копию, проверяет реальный каталог/MP3/повторное открытие кэша и включает отдельный systemd-сервис. Без `--deploy` он только готовит выпуск. Резервные копии credentials не попадают в исходники или отчёты.

Токен бота никогда не добавлять в исходники, URL медиа, логи или публичные отчёты. Бот не изменяет чужой webhook: при существующем webhook запуск прекращается. Второй long poller определяется как конфликт и сервис останавливается.

Проверки: `node --test tests/telegram.test.cjs`; общий запуск `npm test`, синтаксис `npm run check`. Автотесты проверяют настоящую MP3-конвертацию и локальный HTTP, а Telegram-вызовы в unit-тестах подменены. Настоящая отправка из интерфейса Telegram требует действия пользователя; `getMe`, каталог, аудио и публичный MP3 проверяются отдельно при развёртывании.
