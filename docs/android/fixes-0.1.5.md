## Что исправлено

| Сценарий | Поведение 0.1.5 |
| --- | --- |
| Удалить последний играющий трек, добавить другой и нажать Play | Новая очередь начинается с нуля. Позиция удалённого трека больше не переносится в новый. |
| Изменить громкость во время приглушения аудиофокусом | Пользовательская громкость меняется, но приглушение сохраняется до возвращения фокуса. |
| Получить позднее событие от прежнего запроса аудиофокуса | Событие не возобновляет пользовательскую паузу и не останавливает новый запрос. Актуальные transient loss/gain продолжают работать. |
| Загрузка закончилась одновременно с закрытием или пересозданием Activity | `offlineSaved` обновляет текущий живой PlaybackService через его main-thread handler; старый Activity binder не используется. |
| Два LibraryStore сохраняют очередь и результат загрузки в разном порядке | Старый HTTPS snapshot не заменяет уже сохранённый локальный источник в очереди и истории. Позиция, лайки и независимые настройки сохраняются. |
| IO worker прерван при сохранении SharedPreferences | Файл не удаляется при rollback, если на его URI уже ссылаются библиотека, очередь или история. |
| Повторно запрошена загрузка того же трека из другого экземпляра Activity | Общая для процесса защита не запускает вторую одновременную загрузку; существующий проверенный локальный файл используется повторно. |

`SharedPreferences.commit()` сначала публикует изменения в памяти, а прерывание ожидания записи может вернуть `false` без отката этой памяти. Поэтому прежнее безусловное удаление destination после ошибки могло оставить библиотеку со ссылкой на удалённый файл. Это поведение подтверждено отдельно на Android; оно также видно в [реализации AOSP](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/app/SharedPreferencesImpl.java#614). Это подтверждённый возможный сценарий сбоя, а не объяснение каждого сообщения о недоступной записи.

Индекс локальных источников инвалидируется при изменении точного JSON библиотеки. Это исключает повторный разбор неизменённой библиотеки при каждом сохранении позиции. Общий CPU или расход батареи в этом аудите не измерялись.

В новом 20-check аудите используется настоящий MediaPlayer и сгенерированный немой MP3. События focus loss/gain подаются детерминированно в настоящий обработчик (`injectedFocusCallbacks: true`); это не проверка звонка или другого приложения на физическом телефоне. Этот прогон не обращается к публичному каталогу (`realPublicHttps: false`). Отдельный 58-check прогон использует настоящий публичный каталог и MP3 (`realPublicHttps: true`, `fakeMediaSdk: false`). Личные аккаунты не использовались; тестовые настройки и сеть восстановлены.

Дополнительные 29/50 проверок выполнены на той же APK 0.1.5 без изменения production-сборки. Social core запущен с `--without-picker`: полный SAF-сценарий, новый личный OAuth и будущий installer этим результатом не заявляются. Результаты отдельных наборов пересекаются и не суммируются в число уникальных пользовательских сценариев.

Проверка публичного манифеста была одним read-only GET: APK повторно не скачивался в этой проверке. Проверка 11 assets доказывает упаковку общего клиента, но сама по себе не доказывает работоспособность внешнего SDK или входа в аккаунт. [Предыдущие проверки текстов и social 0.1.4](fixes-0.1.4.md) остаются историческими, их числа не считаются новым device QA 0.1.5.

Недоступные региональные, закрытые и защищённые источником записи не заменяются другой песней и не открываются через браузерный fallback. SoundCloud для личного прослушивания остаётся нативным; YouTube Music — отдельный WebView-источник. Физические устройства, все Android-прошивки и все внешние OAuth-сценарии этим эмулятором не подтверждены.
