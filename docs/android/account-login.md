# Подключение Android к аккаунту LolzCloud

Вход Lolzteam больше не зависит от форума внутри Android WebView. `/login`, `/auth/lolz` и доверенные OAuth-переходы открывают нативный экран подключения телефона. Публичные форумные ссылки открываются в обычном браузере. Это устраняет сценарий, в котором generic error закрывал проверку браузера, а успешный форумный вход оставался в чужой cookie-сессии.

Приложение запрашивает `POST https://lolzcloud.com/api/desktop/start` и показывает 12-символьный код. По кнопке «Открыть браузер» открывается только полный `https://lolzcloud.com/connect?code=...`. Пользователь входит через Lolzteam, сверяет код и сам нажимает «Подтвердить подключение». Сам вход на форум ещё не означает подтверждение телефона. Автоматизации личного входа, переноса форумных cookies, JS-моста и обхода TLS нет.

`POST /api/desktop/poll` использует закрытый 43-символьный `deviceCode`. Нативный клиент принимает только явный `pending:false` с правильными token/user/expiry. Затем `/api/session` с собственным bearer проверяет подлинность сессии и совпадение аккаунта. Только после этого создаётся host-only `__Host-lc_session` для `https://lolzcloud.com`, с `Path=/; Secure; HttpOnly; SameSite=Lax` и ограниченным сроком. Финальная проверка `/api/session` через эту cookie должна подтвердить тот же аккаунт. Успех обновляет нативное имя/непрочитанное и возвращает к исходной собственной странице комнаты, профиля или списка комнат; прямой `/login` возвращает к профилю.

Cookie сначала считается предварительной. Отмена, устаревший callback и ошибка финальной проверки откатывают только cookie этой операции. Проверяются владелец операции и текущее значение cookie; callback старого входа не удаляет более новую сессию. Предыдущая собственная сессия восстанавливается с Secure/HttpOnly либо удаляется только предварительная cookie, если предыдущей не было. Форумные и браузерные cookies не читаются и не меняются.

Код действует не более 10 минут. Private pending state и проверенный recovery grant не входят в экспорт музыкального профиля, Intent или Bundle; приложение запрещает системный backup. Поворот сохраняет контроллер и код, новое создание процесса восстанавливает только ещё допустимое состояние. Poll работает при открытом экране: обычно раз в 3 секунды, сетевые ошибки получают backoff до 30 секунд, HTTP 429 — минуту. После пяти последовательных ошибок автоматическая проверка останавливается до явного действия пользователя. Просроченный код требует кнопки «Получить новый код».

Отмена и Back не переоткрывают вход по старым `onPageStarted`/`onPageFinished` или при повороте родительского экрана. Возврат остаётся на явном экране входа с кнопкой повторной попытки. SoundCloud main-frame ссылки теперь переходят в нативный каталог через согласованный `native_soundcloud_url`, без автозапуска музыки; официальные Widget iframe комнаты не меняются.

Проверки 14 ноября 2026 года: вся Java приложения компилируется с API 36/Java 8. `AccountPolicyTest` прошёл 52 проверки границ протокола и URL; `AccountCookieCommitTest` — 12 проверок задержанных setters/callbacks, отмены, отката и защиты нового аккаунта.

`LoginInstrumentation` на Android 15/API 35, `emulator-5554`, прошёл 55 проверок: 32 объявленных protocol/controller fixture cases, 22 настоящих native UI/lifecycle checks и ограничение запуска эмулятором. Настоящий `POST /api/desktop/start` создал pending-код; проверены сохранение private state, поворот с тем же контроллером, hardware Back, явная повторная попытка и отсутствие автопереоткрытия входа. Browser Intent содержит полный `/connect?code=...` и блокируется тестом до открытия authentication UI. Личный аккаунт не используется, код не подтверждается и authenticated cookie не создаётся. [JSON-отчёт](verification-0.1.3/android-account-login-verification.json).

На том же production APK `0.1.3`, code `4`, SHA-256 `e5fb9fe5bd07bc5889ab3cb69ffcbfdc482440998c3b8533d108f9bf81781d77` прошли [Social/offline 71](verification-0.1.3/android-social-native-verification.json) и [Back-only 17](verification-0.1.3/android-social-back-verification.json). SHA установленного `base.apk` отдельно сверена с исходным APK. Social fixture отключает стартовый auth JavaScript только в instrumentation; production WebViewClient, WebChromeClient, системный picker, callback и обработка Back остаются настоящими. Переключателей или обходов в production нет.

Повтор: `node android/tests/run-login.cjs`, `node android/tests/run-social-native.cjs --back-only`, `node android/tests/run-social-native.cjs` после сборки production и отдельного test APK. Runners разрешают только изолированный `emulator-5554`; исходные JSON записываются в `android/output/`. Успешное ручное подтверждение реального аккаунта пользователем и загрузка изображения в его серверный профиль этими тестами не утверждаются.
