# LolzCloud для Android: функции и условия готовности

Обновлено 14 ноября 2026 года. Актуальные версии — Android 0.1.4 и ПК 0.9.14. [Исправления 0.1.4](fixes-0.1.4.md) охватывают поиск текста, подготовку аудио, Retry и управление ролями. [Исправления 0.1.3](fixes-0.1.3.md) описывают нативную музыку SoundCloud, подключение аккаунта и Android-обновления. [Аудит общих функций](../mobile-parity-0.9.13.md) относится к предыдущим сборкам. Ниже сохранена подробная матрица условий полного переноса; её будущие пункты не следует принимать за уже выполненные.

## Что уже есть в проекте

Исходно LolzCloud был Electron-приложением для Windows/Linux. В этой задаче добавлен отдельный `android/`: Java-интерфейс, AndroidManifest (min API 26, target API 36), `PlaybackService` на framework MediaPlayer/MediaSession, локальная библиотека, импорт LRC/TXT и проверяемый APK-updater. Android SDK установлен в отдельном каталоге; development APK собирается через `android/tools/build.cjs`, без зависимости от Electron и Gradle.

| Уже реализовано в Android-ядре | Граница реализации |
| --- | --- |
| Общий профиль LolzCloud, аватар/фон, проверенные титулы, друзья, приглашения и входящие | Единый backend и shared UI. Native уведомления с периодической фоновой доставкой; оплата «Слушатель+» оставлена на следующий этап |
| Импорт аудио через системный выбор файлов, локальный поиск, очередь, история, избранное, закладки | Реальные локальные файлы и разрешённые прямые HTTPS-потоки; без передачи лайков аккаунту SoundCloud |
| Воспроизведение, seek, repeat/shuffle, MediaSession, foreground service и уведомление | На framework Android; реальные звонки, Bluetooth и особенности телефонов требуют соответствующих проверок |
| Скорость/высота и аппаратные эффекты | Поддержка зависит от устройства; недоступный эффект не должен выдавать успешное включение |
| LRCLIB auto-search, LRC/TXT и переход по синхронной строке | Настоящий metadata lookup, Retry/уточнение и кэш; пользовательский импорт в приоритете. Spicy и полный редактор таймингов ещё не перенесены |
| Локальная «Волна» из библиотеки | Это очередь своей музыки с учётом любимых и недавних треков; полная SoundCloud-модель и запрет повторов на 24 часа остаются задачей переноса |
| Публичный SoundCloud | Нативный поиск и MediaPlayer: фон, очередь, перемотка, история, локальные лайки, офлайн-файл; доступные полные записи до 20 минут / 20 МБ, без синхронизации личного аккаунта SoundCloud |
| YouTube Music / комнаты | Видимый WebView; у комнаты единый серверный протокол и очередь, но источник комнаты не становится частью native очереди телефона |
| Вход Lolzteam | Подтверждение устройства в браузере, проверка выданной сессии и cookie LolzCloud; отмена и ошибка откатывают только собственную незавершённую запись сессии |
| Импорт/экспорт настроек | Собственный формат `lolzcloud-android-profile` v1; desktop-профиль и зашифрованная облачная копия пока не совместимы |
| Проверка Android-релизов, загрузка и проверка APK, системный установщик | Официальный манифест + независимый GitHub fallback, SHA-256/размер/package/versionCode/signature; переход с 0.1.2 требует ручной установки поверх |

Существующий Node.js-сервер обслуживает собственные сессии, подключение устройства через браузер, комнаты, роли и очередь, чат, SSE, пульт компьютера и зашифрованную облачную копию. Отдельный процесс `music/index.cjs` предоставляет публичный каталог и MP3-кэш для нативного SoundCloud; YouTube через него не передаётся. [Контракт музыкального сервиса](../../music/README.md).

Проверены README, CONTRIBUTING, server/README, server/index.cjs, server/catalog.cjs, server/soundcloud-client.cjs, server/player-services.cjs, интеграции локальной библиотеки, профиля, текстов, волны, YouTube, обновлений и Discord. AGENTS.md в корне, родительском пользовательском каталоге и файлах проекта не найден. Существующие изменения не изменялись.

## Backend, который можно подключить

Все следующие API, кроме health и запуска/опроса подключения устройства, требуют собственной сессии LolzCloud. Название «desktop» в device flow не делает протокол зависимым от Electron.

| Контракт | Текущее поведение | Использование мобильным клиентом |
| --- | --- | --- |
| GET /api/health | Версия, roomProtocol, oauthConfigured, spicyConfigured | Проверка доступности backend и возможностей; не проверка версии Android APK |
| POST /api/desktop/start | Создать одноразовую пару подключения | Открыть полученную страницу подтверждения в системном браузере |
| POST /api/desktop/poll | Опрос по секретному deviceCode | Получить свою сессию после подтверждения; обрабатывать ожидание/истечение |
| GET /api/session | authenticated, публичный профиль, csrf, spicyAvailable | Реальный статус входа; не подменять mock-аккаунтом |
| GET /api/music/search?q=... | До 20 SoundCloud-треков, metadata и публичные URL | Поиск; лимит 30 запросов/мин на пользователя, debounce и отмена предыдущего запроса |
| GET/POST /api/rooms | Список/создание комнат | Лобби; показывать реальный результат и отказ |
| GET/DELETE /api/rooms/:id | Состояние/закрытие | Детали и полномочия ведущего |
| POST /api/rooms/:id/join, /leave, /control, /queue, /message; PUT /state | Роли, управление, очередь, чат | Сохранить протокол аренды и revision, не рассылать локальные файлы |
| GET /api/rooms/:id/events; GET /api/clock | SSE и серверные часы | Переподключение, heartbeat и fallback polling; clock также требует сессию |
| GET /api/lyrics/:spotifyTrackId | Общий Spicy только при серверном ключе | Текст конкретной записи, с атрибуцией и обработкой отсутствия |
| GET/PUT /api/profile | Зашифрованная копия и revision | Совместимый клиентский шифр; API не синхронизирует текущий плеер автоматически |
| POST /api/remotes; GET/DELETE /api/remotes/:id; PUT /state; POST /command | Пульт и очередь команд | Управление компьютером; наличие локального плеера телефона этим не подтверждается |

Сервер принимает собственный bearer формата сессии либо secure HttpOnly cookie. Для cookie-запросов, меняющих данные, обязателен X-CSRF-Token. Запрос с Origin, отличающимся от настроенного server origin, отвергается. CORS-заголовков для сторонних origin нет. Поэтому HTML-прототип на file:// или localhost не может просто подключить fetch к production API: нужны same-origin размещение либо native HTTP-клиент с bearer. Не отключать эти проверки ради макета.

GET /api/music/search сейчас использует api-v2.soundcloud.com и public client_id, извлекаемый из веб-ресурсов SoundCloud. Это существующий технический путь с риском поломки, а не зарегистрированный официальный API-контракт. Он возвращает ссылки треков, не адреса потока для Media3. Официальный SoundCloud API требует отдельной интеграции и доступа приложения; актуальный guide описывает OAuth с PKCE. [SoundCloud API Guide](https://developers.soundcloud.com/docs/api/guide).

## Минимальный путь до версии на телефоне

1. **Концепты и интерактивный UI.** Экраны «Главная/Волна», «Поиск», «Плеер», «Текст», «Библиотека», «Комната», «Звук», «Профиль/обновления». У экрана есть настоящая модель состояния и исход каждого действия; демонстрационные треки и тексты явно отделены от данных аккаунта.
2. **Надёжное Android-аудиоядро.** Kotlin/Compose либо другой UI поверх native service; Media3 для локальных и разрешённых прямых потоков. Сначала реальные локальные файлы: import, queue, repeat, seek, восстановление и фоновый звук. Просто завернуть HTML/Electron интерфейс в WebView недостаточно для подтверждённой фоновой работы.
3. **Существующее облако.** Device flow Lolzteam, комнаты/чат/очередь/пульт и перенос профиля. Можно использовать уже работающий браузерный сценарий как отдельный переход, честно обозначая его; это не равняется native реализации всего API.
4. **SoundCloud account/playback.** Отдельно подтвердить API-доступ и потоковое воспроизведение на телефоне; затем подключать wave/likes/downloads к настоящим возможностям источника. Видимый Widget подходит для прототипа воспроизведения, но не подтверждает фон и произвольный DSP.
5. **Release APK и цикл обновлений.** Сначала стабильный applicationId и release signing; затем debug/test APK и device validation. Для установки поверх последующих версий используется тот же ключ. Не выпускать обновления с одноразовым случайным release-ключом.

YouTube-сценарий проектируется отдельно. Официальные правила API запрещают отделять аудио и создавать скрытый фоновый проигрыватель. Кнопки «скачать MP3», «играть фоном» и DSP нельзя рисовать как гарантированно работающие для YouTube. [YouTube API Developer Policies, III.I](https://developers.google.com/youtube/terms/developer-policies).

## Проверки перед обещанием «все функции работают»

| Область | Проверяемый результат |
| --- | --- |
| Жизненный цикл | Экран погашен, Activity уничтожена/воссоздана, смена ориентации и разрешений: звук и состояние согласованы |
| Аудио | Десять быстрых Next/Previous, seek у конца, repeat one/all, гарнитура, звонок и audio focus не создают двойного воспроизведения |
| Источники | Недоступный/удалённый/региональный трек, истёкший URL и нет сети дают точный статус; следующая запись запускается по правилам |
| Локальные файлы | Отмена выбора, повторный импорт, удаление файла и сохранение URI после рестарта; работа в авиарежиме |
| Авторизация | Истечение/отмена device pairing, logout, просроченный bearer и повторный вход без потери локальной музыки |
| Текст и звук | Обычный текст не получает выдуманные тайминги; скорость корректирует синхронизацию; неподдерживаемый эффект не выдаёт успех |
| Комнаты | Два устройства, один ведущий, передача пульта, reconnect, временная потеря сервера, роли и отсутствие локального доступа у гостя |
| Профиль | Desktop→Android→desktop, неправильный пароль, превышение лимита, повреждённый JSON, конфликт облачной ревизии |
| Обновление | v1→v2 одинаковые applicationId/ключ и больший versionCode; сохранить библиотеку/настройки; отмена установки; неверная подпись; плохой файл; мало места |
| Доступность UI | Системный Back, TalkBack-имена, область касания от 48 dp, крупный шрифт, маленький экран и системные inset |

## Установка и обновления: конкретный контракт экрана

Экран отображает реальную Android-версию и источник обновления. Состояния: «Проверка», «Установлена актуальная версия», «Доступна версия…», «Загрузка…», «Файл проверен», «Открыт системный установщик», «Установка отменена», «Ошибка проверки/загрузки». Текст «Обновлено» допустим только после фактического запуска новой установленной версии. Нельзя менять локальную цифру версии ради демонстрации успешного обновления.

Текущий updater читает `GET https://api.github.com/repos/Artemper52/LolzCloud/releases?per_page=30`, ограничивая ответ 1 МиБ. Он пропускает draft/prerelease и выбирает наибольшую stable Android semver из `LolzCloud-Android-X.Y.Z.apk`, независимо от порядка и версий настольных релизов. Поддерживается также lane `android-vX.Y.Z` с универсальным `LolzCloud-Android-universal.apk` или `LolzCloud-Android-release.apk`. Одинаковая или более новая установленная Android-версия не предлагает загрузку. Если подходящего APK среди последних 30 релизов нет, показывается «Android-релиз ещё не опубликован»; повреждённая структура ответа считается ошибкой проверки, без вымышленного результата.

После явного действия пользователя APK загружается по HTTPS только с адресов этого GitHub-репозитория и разрешённых GitHub CDN, в закрытый cache, максимум 150 МиБ. Проверяются размер, GitHub SHA-256 digest при его наличии, packageName, строго больший versionCode, minSdk и точное совпадение сертификатов подписи установленного приложения. Проверка повторяется перед продолжением после разрешения установки. Затем открывается системный установщик через ограниченный read-only ContentProvider. Хеш не заменяет проверку подписи. При несовпадении подписи данные не удаляются; установка всегда требует системного подтверждения. Если будет выбран Google Play, понадобится отдельный механизм магазина.

Android требует подпись APK и при установке, и при обновлении. Смена ключа без поддерживаемого механизма ротации ломает обычный путь обновления существующей установки; release-ключ и его резервная копия — часть релизного процесса. [Android app signing](https://developer.android.com/studio/publish/app-signing).

Для пути через Media3 используется MediaSessionService; текущее ядро использует framework MediaPlayer/MediaSession в отдельном foreground Service типа mediaPlayback с соответствующими разрешениями. Activity не владеет долгоживущим проигрывателем. [Android background playback](https://developer.android.com/media/media3/session/background-playback). Для выбора отдельных файлов используется SAF без полного доступа к хранилищу; индексирование всей музыкальной библиотеки планируется отдельно через MediaStore и разрешения по версии системы. [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files), [MediaStore audio](https://developer.android.com/training/data-storage/shared/media).

На этом этапе факт существования кликабельных экранов или скриншотов не подтверждает установку APK, background playback, реальные аккаунты и обновление на телефоне. Каждый такой результат фиксируется отдельно после соответствующей проверки.
