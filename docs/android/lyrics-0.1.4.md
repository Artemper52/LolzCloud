# Тексты песен в Android 0.1.4

В Android 0.1.3 экран текста читал только импортированные TXT/LRC из `LibraryStore`. Запроса к провайдеру не было: наличие кнопки «Текст» не означало автоматический поиск. Desktop использует отдельный lyrics engine; этот код не выполняется в Android. Серверный Spicy endpoint принимает Spotify ID и требует авторизованную сессию, поэтому он не решает поиск произвольного MP3 или SoundCloud-записи по метаданным.

Android 0.1.4 добавляет настоящий поиск в [LRCLIB](https://lrclib.net/docs), который поддерживает публичный доступ без ключа. Запросы содержат название, исполнителя и известную длительность записи; никакие cookies, LolzCloud-токены, аудиофайлы или локальные URI туда не передаются. Используются только HTTPS `lrclib.net/api/get` и `api/search`, явный идентификатор приложения, последовательные запросы и пауза между ними. Переадресации не выполняются. Размер ответа, число результатов, длительность запроса и размер текста ограничены. HTTP 429/503 соблюдают `Retry-After`, в том числе при явном нажатии «Повторить».

Поиск начинается при открытии нативного экрана «Текст». Загрузка, ошибка соединения, отсутствие результата и инструментальная запись показаны отдельно. «Повторить поиск» обращается к источнику заново; «Уточнить название и исполнителя» сохраняет данные только для поиска текста этой записи. Это помогает MP3 с плохими тегами и SoundCloud-перезаливам, где указан загрузивший канал. Название и исполнитель самого играющего трека не меняются. Рекламные пометки и обозначения official audio очищаются; remix/slowed/live/cover и другие версии не отбрасываются.

Название и исполнитель должны совпасть с записью источника. Подсветка и переход по строкам доступны только для настоящих LRC-таймкодов при совпадении длительности в пределах двух секунд. Если длительность неизвестна или отличается, показывается обычный текст без перемотки и подсветки; таймкоды не растягиваются и не вычисляются. Улучшенный LRC читается по реальным таймкодам строк, а внутренние word tags не попадают в видимый текст. Пословная синхронизация не заявляется.

Импортированный пользователем TXT/LRC всегда имеет приоритет. Автоматический результат не пишет в поле импортированного текста. Успешные результаты хранятся отдельно в приватном cache: до 24 записей на семь дней. Ошибки и пустые ответы не сохраняются как постоянное отсутствие текста. При смене трека, уходе с экрана или уничтожении Activity запрос отменяется; поздний callback не подменяет текст другого трека. Открытие нативного текста не запускает браузер, не меняет комнатную WebView и не останавливает нативную музыку.

Host-проверки: `node android/tests/run-lyrics-policy.cjs`, с настоящим публичным запросом — `node android/tests/run-lyrics-policy.cjs --live`. Для host Java нужен отдельный `org.json` JAR; в APK он не добавляется, приложение использует встроенный Android `org.json`. Проверены 24 metadata cases, 12 LRC cases и 25 provider cases. Публичный HTTPS lookup документированного LRCLIB-трека вернул подходящий синхронизированный результат; исходный текст в отчёт не выводится. Всего с live lookup — 62 проверки. [Машинный результат](verification-0.1.4/android-lyrics-policy-verification.json).

Дополнительный настоящий metadata probe проверил две песни с кириллицей через тот же `LyricsProvider`: «гной» / «тёмный принц», 89 секунд — найдено 19 синхронизированных строк; «цветы», 98 секунд — 21 строка. В обоих случаях совпали название и исполнитель, `versionMismatch=false`; исходные слова не выводились. Это host HTTPS probe конкретных записей, а не повтор 62 fixture-проверок или доказательство доступности всего каталога. [JSON](verification-0.1.4/android-lyrics-representative-verification.json).

`node android/tests/run-lyrics.cjs` запускает отдельный `LyricsInstrumentation` только на согласованном `emulator-5554` после установки production APK. Provider-ответы в UI-проверке явно синтетические: это позволяет проверить загрузку, ошибку, повтор, пустой результат, другой duration, сохранение уточнённых данных и отмену старого запроса без личного аккаунта. Сам MediaPlayer, его позиция, нативные View, касание строки, приватный cache и импорт работают по настоящему коду приложения.

SHA установленного `base.apk` отдельно сверена. На Android 15/API 35 прошли 29 UI/runtime checks, включая настоящий touch → MediaPlayer seek, подсветку, отсутствие паузы при загрузке текста, import priority и отмену устаревшего ответа. [JSON-отчёт](verification-0.1.4/android-lyrics-verification.json). [Снимок нативного экрана с объявленным тестовым текстом](verification-0.1.4/lyrics-found.png).

Текст может отсутствовать у провайдера; неподходящая версия не будет показана как синхронизированная. Работа конкретной песни и сети на телефоне не гарантируется одним успешным запросом каталога.
