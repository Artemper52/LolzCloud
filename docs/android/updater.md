# Android: официальный канал обновлений

Начиная с 0.1.3, updater проверяет официальный манифест и существующий GitHub-канал независимо. Версия 0.1.2 знает только GitHub: для перехода на официальный канал её владельцу нужна однократная ручная установка APK 0.1.3 поверх приложения, с тем же сертификатом. Удалять приложение или его данные для этого не требуется.

## Контракт публикации

Единственный адрес манифеста: `https://lolzcloud.com/downloads/android-update.json`. HTTP 200, UTF-8 JSON, не более 32 768 байт; перенаправления запрещены. Сначала нужно опубликовать завершённый APK, затем заменить манифест. Размер и суммы берутся из окончательного подписанного файла.

| Поле | Требование для 0.1.3 |
| --- | --- |
| `versionName` | Строка `0.1.3`; стабильная версия `major.minor.patch`, без ведущих нулей, prerelease и build-суффикса; до 128 символов |
| `versionCode` | Целое JSON-число `4`; допустимый диапазон 1…2 147 483 647 |
| `packageName` | Только `com.lolzcloud.mobile` |
| `url` | Только `https://lolzcloud.com/downloads/LolzCloud-Android-0.1.3.apk`; имя точно соответствует `versionName` |
| `size` | Целое JSON-число, точный размер подписанного APK в байтах; 1…157 286 400 |
| `sha256` | Обязательная SHA-256 всего подписанного APK: ровно 64 hex-символа, без префикса |
| `certificateSha256` | Необязательная SHA-256 сертификата подписанта: ровно 64 hex-символа, без двоеточий. Поле можно опустить; `null` не принимается |

Для APK запрещены query, fragment, userinfo, явный порт, другой origin, закодированные/обходные пути и любые перенаправления. Официальный сервер должен отдавать этот неизменяемый файл напрямую по HTTPS. Ссылка на сведения о зеркальном релизе фиксирована: `https://lolzcloud.com/`; произвольный `releaseUrl` из JSON не используется.

## Выбор и установка

Из обоих источников выбирается более новая валидная стабильная Android-версия, независимо от версий настольного клиента. При равной версии предпочтение получает зеркало с известным `versionCode`. Ошибка одного источника не скрывает валидный APK из другого. Зеркальный `versionCode` должен превосходить установленный, а `versionName` — быть новее установленного по semver. Ни равная версия, ни downgrade не предлагаются.

GitHub fallback принимает APK из прежнего официального репозитория и прежние известные GitHub CDN, но теперь требует опубликованный API `digest` вида `sha256:<64 hex>`. APK без проверяемой суммы не предлагается. Если найден новый APK без суммы, пользователь видит причину отсутствия обновления; сообщение о «последней версии» не подменяет эту ошибку. GitHub не может перенаправить загрузку в зеркальный канал, зеркало — в CDN.

Скачивание начинается только после явного действия пользователя. Ограничения размера проверяются по метаданным, HTTP-заголовку и фактически прочитанным байтам. SHA-256 обязательна. Перед передачей системному установщику проверяются:

- пакет APK совпадает с установленным `com.lolzcloud.mobile`;
- настоящий `versionName` APK точно совпадает с предложенным релизом и новее установленного;
- настоящий `versionCode` APK выше установленного и точно совпадает с манифестом зеркала;
- minSdk APK совместим с устройством;
- набор сертификатов подписи APK точно совпадает с установленным приложением; необязательная сумма сертификата в манифесте добавляет проверку и не заменяет установленную подпись.

Проверенный cache-файл дополнительно закрепляется сохранёнными размером и SHA-256. После возврата из разрешения «Установка неизвестных приложений» его сумма, размер, версия, пакет и подпись проверяются заново. Подменённый файл или старое pending-состояние без закреплённой суммы требуют повторной загрузки. Read-only ContentProvider и системный диалог подтверждения сохранены; тихой установки нет.

## Проверка реализации

14 ноября 2026 года: `AndroidReleasePolicyTest` — **95 поведенческих проверок PASS**. Покрыты оба источника, выбор версии, fallback, code/name downgrade, обязательная сумма, подмена пакета в манифесте, URL/host/path spoof, границы размера и отдельные redirect trust lanes. `AndroidReleasePolicy`, `UpdateManager` и существующий `UpdateFileProvider` успешно скомпилированы против Android 36 с Java 8 target. Тестовые классы и временные результаты находятся на D.

Финальный APK этим policy-проходом не собирался и не публиковался. Прежние приватные сигнатуры `validateApk(File)` и `requestInstallation(File)` сохранены для существующего installer harness. Валидация правильного cache-пути закрепляет его сумму и для сценария возврата из Settings. Проверка настоящего установщика на готовом APK описана ниже; чистые policy-тесты не подменяют её.

## Тестовые APK и настоящий установщик

`node android/tests/build-update-fixtures.cjs` готовит отдельный комплект в `android/build/update-fixtures/current/` (в этой среде build — junction на D). Production-сборка не запускается. `current.apk` — точная копия текущего APK из `version.json`, `next.apk` — следующий patch/versionCode с тем же сертификатом, `wrong-signer.apk` — та же следующая версия с отдельным тестовым сертификатом. Для 0.1.3/code4 создаются тестовые 0.1.4/code5. **Следующие APK предназначены только для проверки и не устанавливаются.**

Builder читает готовые `resources.zip`, generated manifest и dex, сверяет dex с текущим APK и переносит только его собственные assets. Основные classes, resources и production APK не изменяются. `metadata.json` закрепляет версии, размеры, SHA-256 и сертификаты трёх файлов. Для текущего production APK проверена сумма `e5fb9fe5bd07bc5889ab3cb69ffcbfdc482440998c3b8533d108f9bf81781d77`.

После подготовки фикстур `node android/tests/build-instrumentation.cjs` включает их и метаданные в отдельный тестовый APK. Несовпадение baseline с `version.json`, изменившийся production APK или контрольная сумма фикстуры останавливают сборку. Без свежих фикстур устаревшие updater assets не переиспользуются.

`node android/tests/run-installer.cjs` запускается только на `emulator-5554` после освобождения общей очереди UI. Runner отказывается понижать установленный versionCode и никогда не передаёт `adb install -d`. Устанавливается только текущая baseline и instrumentation APK. Тест отвергает текущую версию, чужую подпись и повреждённый файл, принимает следующий APK с правильной подписью, проверяет read-only provider, Settings разрешения источника и повторную проверку файла после возврата. Затем открывает настоящий Package Installer, нажимает **Cancel** и подтверждает сохранение исходных versionName/versionCode, библиотеки и темы. Внешний runner возвращает разрешение источника в `deny` даже при ошибке.

14 ноября 2026 года реальный installer runner завершился **PASS: 26 проверок** на `emulator-5554` для APK 0.1.3/code4 с SHA-256 `e5fb9fe5bd07bc5889ab3cb69ffcbfdc482440998c3b8533d108f9bf81781d77`. Подтверждены проверки текущего/нового APK, чужой подписи и повреждённого файла, read-only provider, настоящие Settings разрешения источника, продолжение установки после возврата и системный `com.android.packageinstaller` с кнопками UPDATE/CANCEL. Нажат **Cancel**; до и после установленная версия — 0.1.3/code4, библиотека и тема сохранены, `newerApkInstalled: false`. Runner подтвердил возврат `REQUEST_INSTALL_PACKAGES` в `deny`.

Машинный результат: [android-installer-verification.json](verification-0.1.3/android-installer-verification.json). Production APK не пересобирался, тестовые 0.1.4 не устанавливались, эмулятор оставлен включённым. Проверка опубликованного канала выполнена отдельно от этого fixture-сценария.

## Живая проверка опубликованного канала

После публикации `https://lolzcloud.com/downloads/android-update.json` выполнена настоящая проверка из профиля установленного 0.1.3/code4 на `emulator-5554`: нажата только кнопка «Проверить обновление». Фактический ответ приложения: **«Установлена Android-версия 0.1.3. Более новая проверяемая версия не найдена.»** Кнопка осталась «Проверить обновление», установщик не открывался. Скриншот проверен визуально: текст полностью виден и читаем.

Публичный манифест вернул HTTP 200, `com.lolzcloud.mobile`, 0.1.3/code4, размер 2 504 048 байт, SHA-256 `e5fb9fe5bd07bc5889ab3cb69ffcbfdc482440998c3b8533d108f9bf81781d77` и SHA-256 сертификата `84305e6af2473179b6e124a1822eb82c0343e9bba0b5480cd5a91ecc0dceaa44`. Это совпадает с проверенной production-сборкой. Данные и APK приложения этим шагом не менялись.

Результат **PASS: 5 проверок**: [android-update-live-check.json](verification-0.1.3/android-update-live-check.json), [реальный экран](verification-0.1.3/android-update-current.png). Этот проход подтверждает принятие живого манифеста и корректную обработку уже установленной версии; загрузка и установка будущей версии через публичный канал здесь не выполнялись.
