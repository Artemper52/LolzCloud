# Android 0.1.2: аудит функций и исправлений

Дата: 14 ноября 2026 года. Версия исходников Android — 0.1.2, `versionCode=3`. Это аудит текущего кода, а не обещание отсутствия любых ошибок или полного переноса Electron на телефон. Реальный прогон APK фиксируется отдельным JSON-отчётом.

## Найденные ошибки

| Воспроизводимый путь | Причина и исправление |
| --- | --- |
| Сохранить добавленный HTTPS-трек офлайн; UI сообщает об успехе, но библиотека продолжает ссылаться на сеть | `StreamDownloads` создавал новый `Track` с тем же ID, а `LibraryStore.add` игнорировал дубликат. Теперь проверенный локальный файл атомарно заменяет исходную запись, включая сохранённую очередь и историю. ID, любимые, тексты и позиция сохраняются; активная служба принимает локальный источник с восстановлением позиции. При конфликте/удалённом треке новый файл не выдаётся за успешное сохранение. |
| Локальная музыка → профиль, вход или пульт | Общий `openOnline` безусловно вызывал `pause`. Просмотр `/social`, `/login`, `/remote` и `/rooms` теперь сохраняет локальное воспроизведение. |
| Локальная музыка → `/social` → `/rooms` → конкретная комната в той же WebView | Прежний pause действовал только на начальный вызов из MainActivity. Теперь реальный main-frame вход на точный HTTPS `/room/<id>` передаёт управление звуком через внутренний native-контроллер уже работающей PlaybackService. Повторный callback той же навигации не делает второй pause. JS-моста нет. |
| Приглашение приходит во время поиска или локального плеера | Раньше native social-доставки не было. Добавлены реальные API-уведомления и глобальный счётчик непрочитанного. Обновление счётчика не пересоздаёт экран и не сбрасывает ввод, фокус или курсор. |
| Выбор собственного изображения профиля внутри Android | Добавлен JPEG/PNG системный проводник только для доверенного top-level `/social` или `/room`. Проверяются текущий HTTPS origin и сфокусированный file input верхнего документа; запрос из provider iframe отменяется. Cancel, новая навигация и уничтожение Activity завершают callback без URI. |
| Системный Back при открытом социальном drawer поверх комнаты | На APK `4a4810…` настоящий hardware Back завершал Activity: HTML dialog не был частью WebView history. Native Back теперь сначала закрывает открытый top-level drawer собственного room-документа; обычный history/finish применяется, если drawer закрыт. Standalone `/social` не перехватывается. Actual before/after regression подтвердил исправление: первый Back сохраняет ту же Activity, WebView, URL и connected player DOM; следующий Back выходит нормально. |

Ранее исправленные сценарии остаются частью регрессии: цельный браузерный вход SoundCloud вместо переноса частичного Google OAuth callback, видимые ошибки WebView и устойчивый 404/retry latch, безопасные ссылки комнат/пульта, корректная упаковка assets с настоящими `/` в ZIP.

## Общая социальная система

Профиль, друзья, изменение фото/фона, проверенные сервером звания и приглашения используют общую страницу `https://lolzcloud.com/social`. Native Android предоставляет входы в разделы и показывает имя/непрочитанное из авторизованных `/api/social/me` и `/api/social/notifications`. Изменение профиля, чтение, принятие и отклонение происходят на странице с серверной CSRF-проверкой. Нажатие native уведомления открывает список для просмотра; оно не принимает приглашение и не входит в комнату автоматически.

Нативный HTTPS-клиент отправляет только `__Host-lc_session` из CookieManager LolzCloud на два фиксированных API-адреса. Cookies не передаются SoundCloud, YouTube или другим доменам, не экспортируются и не попадают в логи. Переадресации выключены, JSON ограничен по размеру и времени. После смены cookie устаревший ответ не применяется. API/login/auth продолжают работать по настоящей сети; локальные HTML/CSS/JS не выдают пользователя за авторизованного.

Первый успешный снимок аккаунта устанавливает тихую базу. Новые UUID уведомлений проходят постоянную дедупликацию по аккаунту. Прочитанные, истёкшие, отклонённые и выключенные серверной/локальной настройкой события не дают новых уведомлений. Смена аккаунта и выход очищают старые native уведомления; приглашение получает системный timeout истечения. Требуются разрешение Android и разрешённый канал «Друзья и приглашения».

При открытом приложении проверка идёт раз в 15 секунд. Фоновый JobScheduler требует сеть и использует период 15 минут, который Android может отложить, в том числе в Doze. Это периодическая доставка, не push. После принудительной остановки, без сети, без входа или без разрешения нельзя обещать мгновенные уведомления. Для настоящей push-доставки потребуется отдельная серверная/Android интеграция; музыкальная foreground-служба для соцсети не используется. [JobInfo.setPeriodic](https://developer.android.com/reference/android/app/job/JobInfo.Builder#setPeriodic(long)), [Doze и доставка сообщений](https://developer.android.com/training/monitoring-device-state/doze-standby), [разрешение уведомлений](https://developer.android.com/develop/ui/views/notifications/notification-permission).

Проверка верхнего документа в image picker нужна потому, что `WebChromeClient` не сообщает origin вызывающего фрейма. Приложение не добавляет `addJavascriptInterface`: такой объект был бы доступен всем фреймам, включая provider iframe. [Android: WebView native bridges](https://developer.android.com/privacy-and-security/risks/insecure-webview-native-bridges), [CookieManager](https://developer.android.com/reference/android/webkit/CookieManager).

## Границы переноса

| Область | Состояние Android |
| --- | --- |
| Локальная библиотека и прямые HTTPS-потоки | Native MediaPlayer/MediaSession, очередь, repeat/shuffle, история, любимые, локальная волна, SAF-доступ, офлайн-файлы, эффекты устройства, таймер, LRC/TXT, закладки и безопасный APK-updater. |
| Комнаты, чат, общая очередь и социальная система | Общий HTTPS backend и bundled app-owned frontend; официальные provider SDK остаются сетевыми. Комната сохраняет общий JS drawer при просмотре профиля. Сервер обязателен. |
| SoundCloud | Цельная обычная Custom Tab/браузерная сессия. Собственного зарегистрированного OAuth-клиента нет. Браузерный вход не является входом native плеера и не переносит библиотеку аккаунта в Android-службу. |
| YouTube Music | Видимая WebView источника; Google-вход запускается цельным сценарием в браузере. Нативное извлечение аудио и гарантированный фон не реализованы. |
| Desktop Wave, радар, группировка версий, тексты из сетевых провайдеров/редактор таймингов, Discord/Voicetag | Полного Android-переноса нет. Локальная волна и пользовательский LRC не подменяют эти функции. |
| Профиль данных плеера | Android-файл настроек остаётся своим форматом. Социальный профиль общий; desktop encrypted cloud backup музыкальных настроек пока не совместим с Android-форматом. |

Отдельные UX-возможности остаются в плане: управление заметками/удалением закладок, отдельная настройка pitch вместо пресетов, полноценный список загрузок с прогрессом и отменой. Они не считаются реализованными только потому, что соответствующий метод существует в службе.

## Проверки этой итерации

- Все production Java и отдельные instrumentation-классы компилируются с API 36 и Java 8; файлы компиляции находятся на D.
- 251 поведенческая проверка без устройства: social/session/upload/notification policy — 56, source/auth/error latch — 58, bundled routing/API boundaries — 66, updater — 41, LRC — 11, ссылки — 19.
- Новый `SocialAndroidInstrumentation` проверяет настоящее private-хранилище и MediaPlayer, сохранение очереди/позиции, переход social→rooms→room, системный JPEG/PNG picker и Cancel, отказ provider frame, реальные NotificationManager/PendingIntent, дедупликацию, настройки и счётчик без потери ввода. Он использует явно синтетические social events, а не личный аккаунт.
- Финальный APK 0.1.2 прошёл **70 native проверок** на `emulator-5554`: Android 15, API 35, x86_64. Сохранены предыдущие 55 сценариев, добавлены 15 проверок системного Back. SHA-256: `cd15baff03a366bdf404ca50eaa3137be212fe9df18b6df5a93e50bae7370b9f`. Отчёт — `android/output/android-social-native-verification.json`; отдельный `android/output/android-social-back-verification.json` содержит 17 passed checks (включая два общих startup checks).
- Успешный путь изображения проверен через настоящий tap по file input, системный `ACTION_OPEN_DOCUMENT`, отдельный PNG DocumentsProvider и штатные production `onActivityResult`/`ValueCallback`. FileReader/Canvas прочитали 108 байт, размер 8×8 и точный RGBA `[85,170,119,255]`. `setAllowContentAccess(false)` сохранён. Cancel, уничтожение Activity и отказ file chooser для provider iframe тоже прошли.
- Реальные NotificationManager и immutable PendingIntent проверены на синтетических событиях: тихая первая база, постоянные ID, отсутствие дублей, серверное выключение, foreground-доставка, снятие прочитанных/истёкших уведомлений, счётчик без потери ввода и переход к просмотру без autoaccept. Harness ожидает фактического результата, поскольку Android снимает системные уведомления асинхронно.
- Изолированная HTML-форма работает на разрешённом собственном HTTPS origin; только на её загрузку harness выключает стартовый auth-redirect script. Production WebViewClient, WebChromeClient и callback выбора файла остаются штатными. Тест не входит в личный аккаунт, не принимает приглашения и не утверждает, что проверил загрузку фото в реальном пользовательском профиле на сервере.
- Для Back используется настоящий `social.js` из APK и явно синтетический UI snapshot без auth cookie и серверных изменений. Системный `KEYCODE_BACK` проверяется через Android input; native callback не вызывается вручную. Standalone social не зацикливает Back, закрытый drawer не блокирует обычный выход. Старый before-failure сохранён отдельно в task-specific D-каталоге; новый отчёт содержит actual PASS.
- Повтор: `node android/tests/build-instrumentation.cjs`, затем `node android/tests/run-social-native.cjs`; отдельный Back-прогон — `node android/tests/run-social-native.cjs --back-only`. Runner разрешает только `emulator-5554`, восстанавливает тестовые настройки и исходное разрешение уведомлений. Единственное production изменение после первого 55-check прогона — обработка Back в OnlineActivity; разрешения WebView не ослаблялись.

Предыдущие реальные device-результаты 0.1.1: [verification-0.1.1.md](verification-0.1.1.md). Аппаратные эффекты, Bluetooth, звонки и особенности конкретных телефонов по-прежнему требуют проверки на соответствующем устройстве.
