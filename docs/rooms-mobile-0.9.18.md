# Комната с телефона: управление музыкой и чат

Новая веб-ревизия 0.9.18 исправляет сценарий, в котором владелец открывал свою комнату с телефона, пока пульт оставался на ПК. Для нового интерфейса подготовлены desktop 0.9.16 и Android 0.1.6. Ранее опубликованные бинарные файлы 0.9.15 и APK 0.1.5 сохраняются без перезаписи.

Подтверждённые ошибки управления:

- Прямой запуск результата поиска показывался только текущему controller. Владелец и назначенный DJ на другом устройстве получали только предложение в очередь. Кроме того, уже показанные кнопки не обновлялись после смены роли/пульта. Теперь «Включить сейчас» доступно по `canControl`; состояние обновляется в существующей выдаче без нового поиска.
- В очереди отсутствовало действие запуска конкретной записи. Добавлен `play-queue` в существующий защищённый control API: активные роль, lease, connection и монотонный sequence проверяются до изменения. Один синхронный commit делает выбранный queue ID текущим, ставит его в начало с паузой до готовности SDK и удаляет только эту запись. Остальная очередь сохраняется, включая другой ID с тем же URL; поздний старый state PUT не возвращает прежний трек.
- Ошибка во время работы с модальным выбором могла остаться за диалогом, в основном статусе комнаты. Теперь доступный live status виден и внутри панели; результаты и повторное действие сохраняются.
- При заблокированном SDK воспроизведение могло оставаться тихим без понятного действия. Есть состояние «Разрешить звук здесь»; повторное явное нажатие разрешает локальный звук, не переключая общую комнату в паузу. Ошибка открытия выбранной записи даёт Retry, который не забирает следующую песню из очереди.

Пульт переносится только после явного нажатия пользователя. Владелец может взять его с другого своего устройства; DJ может занять свободный пульт и получает честный конфликт, если другой controller ещё активен. Listener сохраняет предложение, голосование и локальное прослушивание, но не получает управление всем залом. Поиск, открытие панели и SSE-обновления сами пульт не забирают. Старый трек не запускается ради обхода требования user gesture.

Изменения удобства отделены от этих исправлений. Компактная сцена и transport находятся рядом с музыкой; чат и composer остаются на основном экране. Музыка, очередь и участники открываются в одном диалоге. Закрытие, Escape и Browser Back возвращают в прежнюю комнату; выбранные вкладки имеют ARIA-состояния и клавиатурную навигацию, фокус возвращается на кнопку открытия, включая touch-сценарий без автоматического фокуса кнопки. Исходный player и поле чата сохраняют свои DOM identity и черновик. Панель учитывает visualViewport при клавиатуре.

В Android `OnlineActivity` настройка media gesture теперь отключается только для точной доверенной страницы комнаты, как при первоначальном открытии, так и при последующей main-frame навигации. Для social/login и остальных страниц она включена. Это позволяет завершить выбранное пользователем воспроизведение после асинхронных claim/SDK/Next; само подключение по-прежнему не включает звук до Join/Play. На неизменённом APK 0.1.6 выполнены [13 проверок настоящего WebView и 17 проверок Social Back](android/verification-0.1.6/README.md). Настоящее media в cross-origin iframe запускается после MotionEvent и отложенного fetch; до Join остаётся на паузе. Это явно перехваченные HTTPS fixtures, которые не проверяют личный вход или внешний музыкальный SDK. Social Back отдельно не подтверждает Android Back нового room-sheet.

Проверено на замороженных исходниках:

- **22 browser checks** с настоящими mouse input, HTTP/SSE и серверными ролями на 360/420/1366 px: owner PC→phone, запрет молчаливого захвата, listener/DJ и живое изменение роли, queue ID/Next, blocked/retry, сохранение чата и отсутствие горизонтального переполнения. Каталог и SC/YT SDK объявлены тестовыми адаптерами.
- **24 layout/interaction checks**: 360/390/420/1440 px, landscape и уменьшенный viewport; modal tabs, Back/Escape/focus, длинный чат, touch targets и видимая ошибка в панели.
- **7 новых Node/HTTP tests**: атомарный snapshot, равные URL с разными ID, поздняя старая публикация, смена controller, DJ/revoke/expiry, cookie CSRF, недоверенный Origin и отсутствие авторизации. Ещё **7 существующих room-engine tests** прошли.
- **12 общих room regression scenarios** с host и двумя guest: плановая коррекция за пять секунд, exactly-once seek-end/finish, 1×, pause/seek, чат, локальные volume/mute, роли, reconnect и browser/DJ/desktop handoff. На этом прогоне умеренное тестовое отклонение 0,7 с восстановилось за 2319 мс, большое 9 с — за 645 мс. Это наблюдения fixtures, не SLA внешнего сервиса или физического телефона.
