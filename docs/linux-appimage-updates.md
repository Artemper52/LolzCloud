# Linux AppImage: обновление с проверкой и откатом

Исходники подготовлены для следующего desktop 0.9.17. Прежние AppImage 0.9.15/0.9.16 не менялись; их Linux-клиенту понадобится вручную установить новую версию один раз. Версия из tar.gz обновляется вручную. Этот отчёт не подтверждает публикацию нового Linux-релиза.

Клиент проверяет официальный `https://lolzcloud.com/downloads/platforms.json`. Обновление предлагается только для более новой версии и подходящей архитектуры. Имя, HTTPS-адрес, размер и SHA-256 AppImage должны точно совпасть с ожидаемым versioned-файлом. Редиректы и изменение конечного адреса отклоняются. JSON ограничен 100000 байтами во время чтения, а не после загрузки всего ответа.

До скачивания фиксируются хэш и параметры исходного файла. Изменение файла во время загрузки не становится новой «исходной версией»: операция прекращается до сохранения профиля и выхода приложения. После загрузки повторно проверяются размер, SHA-256, ELF64, архитектура и AppImage Type2 magic.

Помощник работает в отдельном закрытом каталоге рядом с AppImage. Он сохраняет проверенную резервную копию и подтверждает готовность **до** вызова сохранения профиля/выхода. Затем ждёт исчезновения именно исходного PID с тем же временем старта. Пустые, нулевые, нечисловые и неканонические значения PID/startTime отклоняются. После выхода родителя ещё раз сверяются исходный и скачанный файлы, затем выполняется переименование на том же томе. При немедленной ошибке запуска восстанавливается прежний AppImage и запускается снова. Сохранённая резервная копия остаётся в каталоге операции.

Во время скачивания видно продвижение, после него — «Подготовка…», затем сообщение о сохранении профиля и перезапуске. Ошибка загрузки, проверки, блокировки или подготовки оставляет приложение открытым. Провал сохранения профиля создаёт отмену для уже подготовленного помощника. Состояние «готово» не объявляется только по факту скачивания.

| Проверка | Результат | Доказательство |
| --- | --- | --- |
| Linux policy + реальный `/bin/sh` helper | **22 PASS, 0 skipped**, обычный UID 986 | [linux22.log](./linux-appimage-updates/linux22.log) |
| Подтверждение исходных трёх дефектов | 3 ожидаемых падения до исправления: чтение за лимитом, принятый другой адрес, принятая замена исходного файла во время скачивания | [baseline3-failures.log](./linux-appimage-updates/baseline3-failures.log) |
| Настоящие копии AppImage 15 → 16 | **5 PASS**: ожидание PID, резервная копия, замена, native self-test, сохранность оригинальных релизов | [native-appimage-update-results.json](./linux-appimage-updates/native-appimage-update-results.json), [self-test](./linux-appimage-updates/native-appimage-self-test.log) |
| Прежний Windows updater | **17 PASS**, Windows-реализация/portable download не изменены | [windows17.log](./linux-appimage-updates/windows17.log) |

Linux-сценарии включают контроль готовности/резервной копии перед сохранением профиля, отсутствие ранней замены, точный PID/startTime, повторное использование PID, неудачный запуск и откат, отмену, испорченный файл загрузки, изменение назначения после готовности, подмену назначения ссылкой, занятый lock и пути/аргументы с пробелами и апострофом. Для отдельных транзакций скомпилированы небольшие ELF-fixtures с AI02 в свободной части ELF-заголовка. Они явно являются тестовыми программами, а не выпущенными AppImage.

Отдельная проверка использовала настоящие зафиксированные AppImage 0.9.15/0.9.16: только их копии помещались в новый изолированный каталог. Новый 0.9.16 запускался через обычный FUSE с `--self-test` в Xvfb, отдельном D-Bus и разблокированном тестовом GNOME Keyring. Самотест подтвердил Electron 45.2.1 и настоящий renderer. Родитель транзакции здесь — собственный `sleep`; поведение нового контроллера приложения дополнительно проверялось в unit-сценариях, а не выдаётся за уже упакованный 0.9.17 GUI.

Временные native-профили имели проверенный `/tmp/LolzCloud-self-test-*` путь и были удалены. Старые release-файлы сохранили исходные SHA-256. Никакие личные приложения, профили, аккаунты и рабочие службы не обновлялись. В первоначальных QA-проходах исправлены только ошибки harness: недоступный cwd после смены UID, повторное ожидание SIGTERM-процесса с `exitCode=null` и создание D-Bus до установки собственного XDG-каталога. Успешный финальный запуск выполнен после этих исправлений; неудачные логи сохранены отдельно на D.

ARM64 проверен только разбором/выбором архитектуры, без native ARM64 запуска. Физический звук, Wayland, произвольный Linux-дистрибутив и восстановление после аварийного отключения питания не проверены. Транзакция использует резервную копию и атомарное переименование, но этот отчёт не заявляет гарантию при потере питания или успешный запуск всех пользовательских конфигураций.

Входные файлы, точные SHA-256 и местоположение изолированного Linux QA: [verification.json](./linux-appimage-updates/verification.json).
