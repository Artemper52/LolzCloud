# Проверка desktop music для 0.9.15

Проверено 14 ноября 2026 года на Windows в отдельных Electron-профилях с тестовым WAV и подменой сетевых страниц провайдеров. Установленный клиент, личные аккаунты и публичные артефакты 0.9.14 не использовались. Версию и релиз собирает основной агент.

## Подтверждённые исправления

| Сбой | Воспроизведение и исправление |
| --- | --- |
| Локальный звук включался после паузы | Отложенный `AudioContext.resume()` завершался после pause и вызывал `audio.play()`. Отдельный номер команды и намерение воспроизведения отменяют запуск после pause/stop; повторное нажатие корректно возобновляет выбранный трек. До исправления regression был красным. |
| SoundCloud включался поверх локального файла | Обработчик `play-url` повторял попытку до 30 секунд, хотя пользователь уже сменил источник. Изолированный Electron-тест подтвердил настоящий `HTMLAudioElement.paused === false` после запуска локального WAV. Pause, Next/Previous, локальное воспроизведение и переход на YouTube отменяют старую попытку; результат устаревшего callback также отбрасывается. Этот же UI regression прошёл после исправления. |
| YouTube сначала включал отменённую песню, затем ставил на паузу | Pause ждал `trackLoad`, который сам запускал песню. Теперь pause сразу отменяет отложенный autoplay; проверки актуальности стоят после открытия, навигации, получения metadata и seek. Сбой воспроизведён отдельным тестом до исправления. |
| Старый YouTube open откатывал новый выбор | Два перекрывающихся открытия завершались в другом порядке: старое отправляло `playback-source: soundcloud` после нового успешного YouTube. Откат теперь допустим только когда пользователь действительно ушёл из YouTube. Тесты покрывают оба порядка и уход во время открытия. |
| Repeat-all обрывался на недоступном файле у края очереди | Переход через отсутствующий последний/первый файл не обходил очередь по кругу. Теперь обход ограничен длиной очереди, работает в обе стороны и возвращает остановку, если доступных файлов нет. Repeat-one для отключённого файла завершается без исключения. |
| Metadata от буферизованного файла выбрасывала исключение после отключения диска | Обновление длительности требовало существования исходного файла. Оно теперь обновляет только зарегистрированную запись библиотеки; проверка существования остаётся при фактическом открытии аудио. |
| Редактор временных меток YouTube не получал точную позицию | Он обращался к SoundCloud API внутри YouTube guest. Теперь используется позиция реального YouTube media snapshot. UI regression ставит временную метку после seek настоящего тестового video. |

При запуске локального файла отменяются и ставятся на паузу оба сетевых плеера, включая ещё открывающийся YouTube, а также комнатный плеер.

## Нагрузка

Один YouTube sample теперь получает playback и audio state одним `executeJavaScript`, вместо двух последовательных вызовов каждые 250 мс. Это уменьшает число обращений к guest на 50% при прежней частоте обновления. Одновременные poll не допускаются; результат от предыдущего открытия/трека отбрасывается. Это проверка числа обращений и корректности данных, а не измерение общего CPU или батареи.

## Проверки

- 41 целевой Node test прошёл: `desktop-playback-races`, `player-tools`, `youtube-music`, `media-source`, `playback-history`, `repeat`, `downloads`, `linux-build`.
- `node tools/test-player-ui.cjs` прошёл с новым SC → local delayed-autoplay regression. Проверены общий и мини-плеер, seek/repeat/DSP/like, комнаты, очередь, передача управления, локальная пауза, приватность, социальные панели без закрытия комнаты.
- `node tools/test-youtube-ui.cjs` прошёл, включая настоящий seek и постановку временной метки, EQ/rate, Voicetag, общий и мини-плеер. В harness добавлено ожидание появления импортированного Voicetag вместо обращения к кнопке до обновления DOM.
- MP3 действительно конвертирован комплектным ffmpeg; кириллические title/artist прочитаны обратно.
- `git diff --check` для изменённых файлов прошёл.

Профили и UI-снимки использовали `TEMP`, `TMP` и `LOLZCLOUD_UI_ARTIFACTS` на D:. Снимки: `D:/LolzCloud-Android-Toolchain/desktop-music-audit-0915/`.

## Linux и границы результата

Проверены переносимые `path.join`/`pathToFileURL`, разрешение ffmpeg вне `app.asar`, существующая политика настоящего keyring и сохранение executable modes в tar при сборке на Windows. Windows ducking на Linux честно обозначен как недоступный. Реальный Linux GUI, аудиоустройство и OAuth этих сервисов в этом прогоне не проверялись; Linux smoke выполняется отдельно при сборке. Здесь нет утверждения об успешном личном входе или доступности каждой внешней записи.
