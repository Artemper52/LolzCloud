# Аудит Android и ПК: профили и комнаты

Этот отчёт относится к Android 0.1.2. В 0.1.3 добавлены нативный каталог и воспроизведение SoundCloud, новый вход и официальный Android-канал обновлений: [актуальные изменения и проверки](android/fixes-0.1.3.md). Результаты прежнего аудита ниже сохранены для своей версии.

14 ноября 2026 года. Сборки: **Android 0.1.2 / code 3**, **Windows 0.9.13**. Общий backend уже развёрнут на `https://lolzcloud.com`: `roomProtocol=2`, `socialProtocol=1`. Это аудит кода и перечисленных сценариев; результаты физических гарнитур, звонков, Doze и личных аккаунтов не подменяются эмулятором.

## Что добавлено на обеих платформах

- Социальный профиль отдельно от резервной копии настроек плеера. Имя и исходный аватар определяет подтверждённый вход Lolzteam. Можно загрузить собственный JPG/PNG, вернуть форумный аватар, выбрать свой фон и заполнить описание. Изменения хранятся на сервере и доступны с обоих устройств.
- Титулы импортируются из настоящих `user_groups` и `curator_titles` ответа `/users/me`: например, «Местный», «Постоялец», «Куратор», звания сотрудников. Редактируемый `custom_title` не используется как подтверждение группы. Клиент не может назначить себе титул или ранг. Данные обновляются при входе; старая сессия не перезаписывает более свежий профиль. [Официальная схема Get User](https://lolzteam.readme.io/reference/usersget.md).
- Ранг LolzCloud отделён от форума. Базовый — «Слушатель»; «Слушатель+» поддержан серверной моделью. По решению пользователя платный статус и оплата оставлены на следующий этап; интерфейс не изображает работающую покупку.
- Заявки в друзья, принятие, отклонение, отмена и удаление. Добавить человека можно прямо из комнаты или найти среди зарегистрированных пользователей LolzCloud.
- Приглашения друзьям в текущую комнату, отдельные входящие и непрочитанный счётчик. Приглашение действует час, проверяет участника, получателя, бан и доступность комнаты. Просмотр уведомления не принимает приглашение и не включает музыку автоматически.
- Настройки заявок, приглашений и уведомлений. Новые события приходят через SSE с HTTP fallback. Android использует настоящие NotificationManager и immutable PendingIntent; ПК — Electron Notification с постоянной дедупликацией по аккаунту. Нажатие ведёт во входящие для явного решения.
- Новый чат: аватары и профиль автора, титул, время, группировка сообщений, непрочитанное, сохранение чтения и черновика. Профиль, друзья и входящие открываются поверх комнаты, сохраняя тот же плеер, подключение и очередь.

Общий клиент `server/public` упакован в APK и desktop ASAR; backend, OAuth и SDK источников остаются сетевыми. Android/ПК используют одну модель ролей, DJ, ведущего, аренды управления, очереди, голосов, чата, истории и приглашений. Плановая коррекция позиции каждые 5 секунд и защита от двойного Next сохранены.

## Найденные и исправленные ошибки

| Сценарий | Исправление |
| --- | --- |
| Сохранённый Android-поток оставался HTTPS-ссылкой при сообщении «доступен офлайн» | Атомарная замена записи с тем же ID и сохранённой очереди/истории. Активный MediaPlayer переключается на локальный файл с прежней позицией; лайки и тексты сохраняются. |
| Профиль, вход и пульт останавливали локальную музыку | Просмотр вспомогательных страниц сохраняет звук. Настоящий переход в `/room/<id>` приостанавливает локальный источник, включая маршрут из уже открытого профиля. |
| Android Back из профиля закрывал комнату | Воспроизведено на первом кандидате. Первый Back закрывает настоящий social drawer; Activity, WebView и подключённый плеер сохраняются. Следующий Back работает обычно. |
| Новое сообщение чата стирало более свежий черновик | Подтверждение отправки очищает только отправленный текст, если пользователь ещё не изменил поле. Дублирующая отправка заблокирована. |
| Переподключение/выход в рабочей копии теряли часть исправлений релиза 0.9.12 | Перенесены token-bound ответы, защита stale claim/release/publish, закрытие комнаты, поздние callbacks плееров, Esc и 13-раздельная навигация. Новые social изменения сохранены. |
| Старый сеанс возвращал прежний аватар и титулы после нового входа | Сервер сравнивает время проверки Lolzteam и сохраняет более свежую идентичность. |
| Открытые вкладки получали 403 после перезапуска сервера | CSRF сохраняется вместе с сессией. Для прежних сессий общий request helper обновляет его и повторяет действие один раз, только при том же аккаунте и действительно изменившемся CSRF. |
| Отозванная сессия продолжала получать room SSE | Проверка отзыва выполняется при каждой отправке состояния. Это подтверждено настоящим HTTP/SSE тестом. |
| Отменённые загрузки фото могли исчерпать вечный лимит | Очищаются только неиспользуемые собственные uploads; текущие аватар и фон сохраняются. Есть ограничения размера, формата и числа файлов. |

## Что на Android ещё отличается от ПК

| Функция ПК | Android 0.1.2 |
| --- | --- |
| SoundCloud-аккаунт, его библиотека и полноценная нативная очередь онлайн | SoundCloud целиком открывается в браузерной сессии. Собственного OAuth-клиента пока нет; это не native streaming или синхронизация лайков аккаунта. |
| «Моя волна» SoundCloud, радар, группировка версий, запросы музыки словами | Есть локальная волна своей библиотеки; полный настольный рекомендатель не перенесён. |
| Автоматические сетевые тексты, Spicy и редактор таймингов | Native Android импортирует LRC/TXT и умеет переходить по строке; автоматические провайдеры и полный редактор остаются различием. |
| Зашифрованная облачная копия настроек плеера | Социальный профиль общий; Android-файл музыкальных настроек пока несовместим с desktop AES-GCM backup. |
| Менеджер загрузок с прогрессом, отменой и конвертацией | Есть сохранение разрешённого прямого аудио и исправленное офлайн-воспроизведение; полный менеджер ПК не перенесён. |
| Discord RPC, Voicetag, Windows audio-ducker и отдельное окно мини-плеера | Это настольные интеграции. Android имеет собственную MediaSession, уведомление и встроенный мини-плеер. |
| Дополнительное редактирование закладок и отдельных параметров звука | Закладки и пресеты работают; заметки/удаление закладок и отдельный pitch control требуют дополнительного интерфейса. |

Подробный разбор native-кода: [Android audit 0.1.2](android/audit-0.1.2.md). Таблица описывает фактические различия, а не выданные за готовые функции.

## Уведомления и авторизация

При открытом Android-приложении новые события проверяются раз в 15 секунд, показываются системным уведомлением и общим счётчиком. При закрытом — используется сетевой JobScheduler с периодом 15 минут; Android может отложить его. Это не мгновенный push после закрытия или force-stop. Требуются разрешение уведомлений и разрешённый канал. Для мгновенного push нужен отдельный транспорт, а музыкальная foreground-служба для этого не используется.

На ПК системные уведомления подавляются при активном окне, а непрочитанное видно в интерфейсе. Native routing, настройки, дедупликация и смена аккаунта проверены тестами; физический баннер Windows отдельно не наблюдался. Личный успешный вход Google/Lolzteam и уведомления реальным знакомым в тестах не выполнялись. Вход на старом аккаунте может потребовать повторной авторизации Lolzteam для появления ранее не сохранённых титулов.

## Проверка и сборки

- **259 Node-тестов**, включая 13 новых backend сценариев, сохранение старых данных, авторизацию, ревизии профиля, изображения, дружбу, приглашения, приватность и отзыв SSE.
- **30 shared social UI checks**: настоящий DOM, локальный HTTP/SSE, несколько пользователей, file input → Canvas → upload → save, 403 и 409, мобильная ширина 360 px.
- Полный room regression: ведущий/DJ/гость, передача управления, очередь и duplicate finish, смена провайдера, 1×, reconnect, коррекция обычного drift за 2343 мс, срочного — за 373 мс в SDK-фикстурах.
- **31 целевая desktop проверка** и настоящий Electron UI: три варианта комнаты, каждый через 13 панелей; profile/friends/inbox сохраняют музыку, webContentsId и черновик; social не получает room controller API.
- **251 pure Java case** и **70 actual Android checks** на итоговом APK. Настоящий PNG DocumentsProvider → системный проводник → production callback → FileReader/Canvas с точным пикселем; реальные MediaPlayer, NotificationManager и PendingIntent. Отдельный Back-прогон — 17 проверок.
- **11 APK assets** совпадают с исходниками по байтам и сырым ZIP-путям; **9 общих файлов** в desktop ASAR совпали с теми же исходниками. APK подписан прежним development-сертификатом; Windows Setup собран через NSIS.

Музыкальные SDK в автоматических web-тестах заменены детерминированными адаптерами; HTTP, SSE, IPC, окна и действия интерфейса настоящие. Тестовые аккаунты, фотографии и аудио явно обозначены и не входят в пользовательский APK.
