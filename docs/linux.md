# LolzCloud для Linux

Сборки выпускаются для **x86_64** (`x64`) и **ARM64** (`arm64`):

- `LolzCloud-VERSION-linux-ARCH.AppImage` — один исполняемый файл.
- `LolzCloud-VERSION-linux-ARCH.tar.gz` — переносимая папка приложения.

Нужен современный настольный Linux с **glibc**, GTK 3, NSS, ALSA и рабочим графическим сеансом. Цель — поддерживаемые выпуски Ubuntu, Debian, Fedora и другие совместимые дистрибутивы. Это не обещание совместимости с любой версией Linux: Alpine/musl, 32-битные системы и устаревшие дистрибутивы не поддерживаются. В ARM64-системе используется ARM64-сборка.

## Запуск

AppImage:

```sh
chmod +x LolzCloud-*-linux-x64.AppImage
./LolzCloud-*-linux-x64.AppImage
```

Если в системе нет FUSE 2, AppImage поддерживает извлечение и запуск без FUSE:

```sh
./LolzCloud-*-linux-x64.AppImage --appimage-extract-and-run
```

Переносимая версия:

```sh
tar -xzf LolzCloud-*-linux-x64.tar.gz
./LolzCloud-linux-x64/LolzCloud
```

Для ARM64 замени `x64` на `arm64`. Права запуска уже сохранены внутри tar.gz, в том числе при сборке архива из Windows. Приложение запускается от обычного пользователя и сохраняет данные в `~/.config/LolzCloud` или соответствующей папке `XDG_CONFIG_HOME`.

## Вход и интеграции

Для безопасного сохранения аккаунтов нужен разблокированный **GNOME Keyring / libsecret** или **KWallet**. LolzCloud не записывает ключи через незащищённый `basic_text` backend. Если хранилище недоступно, существующая привязка остаётся на диске, а приложение повторяет попытку чтения. При переносе на другой компьютер нужно войти заново: системные ключи не переносятся вместе с папкой приложения.

Обычное воспроизведение, эффекты, текст, волна, комнаты и Discord Rich Presence используют общую реализацию. Нужен запущенный настольный Discord; браузерная версия Discord не предоставляет локальный RPC. Автоматическое приглушение по звуку **других приложений** пока доступно только в Windows. Лимитер громкости самой музыки работает в общем аудиодвижке.

Положение и режим «поверх окон» мини-плеера зависят от оконного менеджера. В Wayland композитор может ограничивать перемещение и удержание поверх других окон. Системный трей зависит от поддержки StatusNotifier в окружении; его отсутствие не мешает запуску приложения.

Сборки сохраняют Chromium sandbox. Если дистрибутив блокирует unprivileged user namespaces политикой AppArmor, необходима соответствующая политика для установленного приложения. Отключение sandbox не добавляется в запуск.

## Сборка из исходников

Node.js 24 и npm:

```sh
npm ci
npm run check
npm test
npm start
```

```sh
npm run build:linux
npm run build:appimage
```

`build:linux` создаёт папку и tar.gz, `build:appimage` требует нативный Linux той же архитектуры. Для кросс-сборки папки и tar.gz:

```sh
LOLZCLOUD_BUILD_ARCH=arm64 npm run build:linux
```

FFmpeg скачивается из закреплённого релиза `ffmpeg-static b6.1.1` с проверкой SHA-256 и архитектуры ELF, вместе с лицензией и описанием конкретной сборки. Для AppImage закреплён `appimagetool 1.9.1`, также с проверкой SHA-256. Windows-версия FFmpeg не попадает в Linux-пакет.

GitHub Actions собирает Linux x64 и ARM64 на отдельных нативных runners, запускает модульные проверки, нативный FFmpeg и сохранение входа в двух отдельных процессах Electron с настоящим GNOME Keyring через D-Bus. Проверки Windows дополнительно запускают интерфейс и аудиодвижок. Публикация релиза начинается только после успешного завершения обеих платформ. Linux GUI на каждом дистрибутиве автоматически не проверяется.

Поддержка платформ описана в [Electron](https://github.com/electron/electron/blob/main/README.md#platform-support), особенности Linux-хранилищ — в [safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage).
