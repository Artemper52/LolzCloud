# Локальная музыка и свой текст в PWA

Это дополнение к веб-клиенту после первой публикации 0.9.15. Оно относится к новой ревизии исходников и веб-приложения; прежние опубликованные архивы 0.9.15 не заменяются. Публикацию новой ревизии выполняет координатор отдельно.

В «Моя музыка» выбери файлы с устройства. За один раз можно добавить до 20 файлов, каждый до 20 000 000 байт. Поддержаны MP3, WAV, M4A и FLAC при условии, что браузер действительно может их воспроизвести. Проверяются расширение, заголовок контейнера, готовность декодера и длительность. Повреждённый или неподдерживаемый файл не создаёт запись. Если добавлена только часть файлов, интерфейс показывает количество добавленных и ошибок.

Сохраняется копия в IndexedDB; исходный файл устройства не изменяется. Для локальной музыки и загрузок SoundCloud используется один атомарно проверяемый лимит 256 МиБ. Новая схема IndexedDB 2 сохраняет прежние `tracks` и `lyrics`, добавляя отдельное хранилище `userLyrics`. Сам импорт сохраняет существующие очередь, выбранный трек и iframe комнаты. Воспроизведение импортированной записи запускается явным нажатием.

Каждая запись получает идентификатор `local:<UUID>`, `source:'local'`, `local:true` и пустой `audioUrl`. Для неё используются только Blob из IndexedDB или собственный реестр файлов нативной оболочки. Локальные пути, `file:`/`content:` URL и неподписанные сетевые адреса не принимаются. Отсутствующий файл вызывает понятную ошибку с предложением повторить импорт; обращения к `/music/prepare` и `/music/audio` не происходит.

Сетевой парсер `track/page` по-прежнему принимает только числовые ID и собственные подписанные MP3. Отдельный `savedTrack` разбирает локальные записи для библиотеки, очереди и native bridge. Любимое, моменты, повтор и случайный порядок используют тот же локальный ID после перезапуска.

В плеере на вкладке текста выбери TXT или LRC до 512 КиБ в UTF-8. Для LRC нужны строки с отметками времени. Свой текст хранится отдельно от LRCLIB и ручного уточнения названия/исполнителя и имеет приоритет над сетевым кэшем. Строки LRC перематывают настоящий плеер и подсвечиваются по текущей позиции. TXT показывается обычным текстом, включая любые символы HTML. Ошибка нового импорта сохраняет прежний свой текст. «Убрать свой текст» возвращает обычный поиск/кэш.

В native bridge кнопка вызывает `importAudio`; результат приходит через `lolzcloud:download` с `import:true`, полным списком записей и состояниями `loading/ready/error/list/cancelled`. JavaScript передаёт локальную запись с пустым URL и `queueIndex` выбранного элемента. Индекс позволяет различать несколько копий одного трека в очереди. Проверен контракт JavaScript с адаптером; реальный UIDocumentPicker и AVPlayer на Apple-устройстве этим отчётом не подтверждаются.

Новый service worker v2 полностью кэширует оболочку, включая `imports.js`, и затем активируется. Проверено обновление уже открытого клиента с worker v1: новый модуль становится доступен для следующего запуска без сети, сохраняя данные и аудиоэлемент.

Проверки 14 ноября 2026:

- 17 сценариев импорта в изолированном Chromium: настоящий DOM file input → File → заголовок/декодер → Blob → IndexedDB → HTMLMediaElement, миграция схемы, частичные ошибки, сохранение очереди/комнаты, LRC seek/highlight, приоритет TXT, некорректный UTF-8, worker v1→v2, перезапуск без сети, локальные любимое/моменты и общий атомарный лимит. В этом браузере успешно открылись все четыре формата.
- 54 общих браузерных сценария: прежние функции поиска, проигрывания, очереди, текста, комнаты, offline, скорости/таймера/моментов; дополнительно native import/local play и выбор второго экземпляра одного трека через `queueIndex`.
- 8 точечных проверок поиска текстов после добавления `userLyrics`.
- 10 проверок политики, включая строгую границу сетевых и локальных типов, заголовки контейнеров, UTF-8/размер/тип текстового файла.
- 5 проверок настоящего заблокированного обновления IndexedDB в двух окнах: поздний успешный результат уже отклонённого запроса закрывается; повтор создаёт ровно одно живое соединение, повторные чтения используют его, а следующая смена версии закрывает его без утечек. После исправления повторно пройдены 17 проверок импорта.

Результаты находятся в `docs/ios-pwa/`: `pwa-imports-results.json`, `pwa-idb-results.json`, `pwa-ui-results.json`, `pwa-lyrics-results.json`; фактические снимки — `local-library-360.png` и `local-lrc-player-360.png`. Источники аудио в проверке сгенерированы ffmpeg. Предыдущее скачивание и давление на квоту моделируются контролируемыми записями IndexedDB. LRCLIB и native message handler заменены явными адаптерами. Физический Safari, системный picker iOS, подпись IPA и Xcode-сборка здесь не заявляются.

Запуск узкой проверки: установи `LOLZCLOUD_PWA_TEST_SUITE=imports` и запусти `node tests/run-pwa-ui.cjs` с изолированными TEMP/TMP и `LOLZCLOUD_PWA_TEST_OUTPUT` на D, как описано в [основном отчёте](./ios-pwa.md).
