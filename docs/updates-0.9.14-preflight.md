# Проверка временной папки обновления · 0.9.14

В 0.9.14 установленный Windows-клиент проверяет временную папку и место на диске до `prepareRestart`. Порядок сохранён: скачивание штатным `electron-updater` → размер и SHA-256 установщика → проверка места и записи → сохранение/завершение сессии → штатный `quitAndInstall`.

Если системный TEMP переполнен, выбирается доступная для записи папка `.LolzCloud-update-temp` **рядом с каталогом установки**, на том же диске. Она находится вне каталога приложения, чтобы деинсталлятор её не удалил. Проверяются канонический путь, диск, свободное место и запись небольшого собственного probe-файла. Существующие системные папки и пользовательский кэш не переносятся и не очищаются.

Оценка требует минимум **1536 МиБ** для распаковки и 512 МиБ для замены приложения; для больших установщиков запас увеличивается пропорционально размеру. Для измеренного payload 0.9.14 реальная проверка NSIS требует 1 220 677 632 байта (1165 МиБ); прежней границы 1024 МиБ было недостаточно. Теперь C со свободными 1100 МиБ отклоняется и при доступном D выбирается альтернативная папка. Если временная папка и установка находятся на одном диске, требования распаковки и замены складываются. Если безопасного места нет, пользователь получает ошибку до закрытия приложения. Ошибка ENOSPC при скачивании в кэш Windows также завершается понятным сообщением без `prepareRestart`.

TEMP/TMP меняются только в текущем процессе непосредственно перед запуском штатного установщика; дочерний NSIS наследует выбранный путь. Глобальные настройки Windows не меняются. Синхронная ошибка запуска восстанавливает прежние значения и отсутствие переменных. Хеши, прогресс, проверка версии и штатный кэш `electron-updater` сохранены; внутренние cache API библиотеки не подменяются. `allowDowngrade` остаётся выключенным после назначения канала.

## Подтверждённые проверки

**17 тестов PASS**, без запуска установщика в этом проходе. Покрыты полный C при доступном D, пограничные 1100 МиБ на C при доступном D, отсутствие безопасной альтернативы, запрет временного пути внутри удаляемого каталога приложения, недоступная запись, неизвестное свободное место, заполненный download cache, проверка суммы до закрытия, сохранение окружения при ошибке, реальный файловый probe без изменения тестового профиля и ранний выход второго экземпляра после `app.quit()`.

Для Electron 22/Node 16 без `fs.statfsSync` предусмотрен ограниченный по времени read-only `DriveInfo` через PowerShell. Путь передаётся данными на stdin, не вставляется в код команды. Этот fallback проверен на текущем Windows-хосте: обычный statfs и DriveInfo независимо вернули **54 788 939 776 байт** на D. Это значение на момент проверки, а не текущая оценка или резервирование места.

[Машинный отчёт с именами всех 17 тестов, результатом реального probe и SHA-256 замороженных исходников](updates-0.9.14-preflight.json).

Исходная проблема и фактическое восстановление установленной 0.9.13 зафиксированы отдельно: [updates-0.9.13-installation.json](updates-0.9.13-installation.json). Там проверенный NSIS с системным TEMP завершался кодом 112, а с временной папкой на D успешно установил 0.9.13; версия проверена в registry и app.asar, 13 файлов JSON профиля не изменились. Это отдельное доказательство причины сбоя, не результат установки 0.9.14 данным тестом.

Новая 0.9.14 этой проверкой не устанавливалась. Большинство отказов диска/нативного updater воспроизводились зависимостями тестов; отдельно выполнены настоящий файловый probe и настоящий read-only DriveInfo. Полная установка на Windows 7 не выполнялась. Preflight проверяет доступность и место, но не резервирует ёмкость и не объявляет установку завершённой. При подготовке документации production-код, версия пакета, сервер и устройство не менялись.
