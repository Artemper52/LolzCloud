# Music + Telegram: проверка обновления 15 ноября 2026

Статус: опубликовано и проверено. Обновлены только музыкальный сервис и бот; основной сервер `0.9.22` и PWA/SW7 сохранены. [Машинный отчёт](service-hotfix-2026-11-15/verification.json).

Исправление сохраняет проверенные публичные метаданные песен после записи/повторной загрузки состояния. Ограниченная проверка старых записей использует точные ID и URL. Бот также получил исправление проверки полного MP3 с прикреплённой обложкой: длительность определяется декодированием аудиодорожки, без влияния временной шкалы картинки.

Перед остановкой каждого сервиса отдельный каталог под его UID подтвердил реальный поиск SoundCloud, сохранение метаданных и полный MP3. Музыка дополнительно вернула 20 записей волны при запросе 56 764 байта. После переключения публичный запрос волны 62 598 байт тоже вернул 20 записей.

Независимая проверка с Windows и read-only SSH завершилась **17/17**: оба реальных процесса используют новые каталоги и правильные UID, все файлы совпали, на сервере ровно один процесс опроса Telegram. Публичные MP3 обоих сервисов: 1 799 586 байт, SHA-256 `44bcf81d69ffdb38b5efc3706b8668fec4d2ca79ff96de1b77447ab482f6512b`, Range 206/128 байт с ID3, обложка APIC. Аудио декодируется в 111,502 с при метаданных 111 с. [Публичная проверка](service-hotfix-2026-11-15/public-verification.json), [музыка](service-hotfix-2026-11-15/music-verification.json), [бот](service-hotfix-2026-11-15/telegram-verification.json). Это отдельные runtime-проверки; исходные 88 тестов владельца исправления не суммируются с ними.

Сохранены исходная позиция опроса, 1 кешированный file_id и 1 брендовый ресурс бота; наружу выведены только количества и результаты сравнения. Env, systemd units и nginx побайтово сохранены. Резервные копии остались только на сервере: каталоги 0700, приватные файлы 0600; предыдущие release-каталоги сохранены.

Первая предварительная проверка остановилась до stop/start: Node stdin под сервисным UID наследовал недоступную папку `/root`. Исправлен только deployment harness — задан каталог проверяемого release. Перед продолжением существующий stage повторно сверили с полным манифестом; повторного переключения после неопределённого сетевого результата не было.

Ручные сообщения, изменения профиля/команд Telegram и отдельные вызовы getUpdates не выполнялись. Проверена нормальная работа существующего опроса и настоящая HTTP-доставка медиа; доставку конкретному получателю Telegram не проверяли. Пользовательские аккаунты и комнаты не изменялись.
