# Выбор записи очереди в desktop 0.9.16

Проверка запускает production Studio, IPC и изолированный room WebView через development Electron 45.2.1. HTTP/SSE обслуживает настоящий локальный CloudStore/RoomEngine; страницы музыкального сервиса и аудиозаписи являются объявленными fixtures. Release executable отдельно прошёл native self-test. Эти виды проверки не смешиваются.

В очередь добавлены две записи настоящим авторизованным HTTP-запросом. Попытка добавить одинаковый URL получила штатный 409. Третья запись с таким URL и другим ID явно подготовлена как legacy/restored state только в изолированном store. Нажатие средней записи в панели очереди прошло через room-preload и защищённый rooms:desktop IPC, атомарный control API и настоящий YouTube WebView. В service подтверждены нужный URL и играющее media; оставшиеся первый и третий ID сохранены.

Предыдущий state PUT был принят сервером, но его ответ удерживался до готовности нового трека. После освобождения ответа 39 последующих native samples оставались на выбранной играющей записи; HTTP-публикации имели более новые sequence и тот же URL. Не изменились identity room guest, скрытого provider iframe и черновик чата. Две оставшиеся записи затем удалены настоящим HTTP API; прежние сценарии handoff и навигации по 13 панелям у listener, YouTube host и SoundCloud host прошли.

Отдельно прошли восемь Node-проверок: публикация во время подготовки, поздний успешный/отклонённый heartbeat, пауза нового displayPlayback до готовности, приватность, выход во время выбора, повторное нажатие и недействительный ID/lease. Все 358 общих Node-тестов прошли.

Windows modern и legacy собраны штатными packager/NSIS. Обе сборки прошли native self-test на текущей Windows. Изолированная реальная установка 0.9.15 → 0.9.16 сохранила настройки, историю, закладки и зашифрованные сессии; недостаток места останавливает установку до изменения приложения. Legacy здесь не проверялся на физической Windows 7.
