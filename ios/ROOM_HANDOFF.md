# Комнаты, импорт метаданных и сохранённая музыка: кандидат

Опубликованные исходники и доказательства iOS 0.1.5 не изменяются этим описанием. Новая реализация проходит Foundation policy tests и синтаксический разбор Swift; сборка Apple SDK и новые hosted XCTest ещё ожидаются.

Владельца комнаты назначает только доверенный главный документ `/app/` через существующий WK bridge. `roomOwner` содержит текущие `clientId/requestId`, `roomId`, новый для документа `documentId`, независимые `epoch/revision`, `active`, снимок `playback` и пять разрешений `play/pause/next/previous/seek`. Новая capability — `roomTransport:1`. Старые приложения её не объявляют.

При захвате комнаты NativePlayer отменяет старые подготовки/EOF/ready callbacks по поколению, приостанавливает AVPlayer и освобождает его item. Сольная очередь и позиция остаются для будущего явного выбора. Системные команды проходят через тот же `mediaCommand`, который использует MPRemoteCommandCenter: активная комната получает `lolzcloud:room-command` с UUID команды и точным владельцем. Кнопки доступны по снимку разрешений; Previous означает начало текущей записи комнаты. ACK не изображает воспроизведение: статус и позиция меняются по последующим реальным снимкам комнаты.

Доставка ограничена тремя секундами и восемью незавершёнными командами. Точный `roomCommandResult` с `ok:true,pending:true` один раз подтверждает доставку и даёт до 60 секунд на завершение, максимум 63 секунды от создания. Повторное pending не продлевает срок. Итоговый ACK удаляет команду; ошибка или истечение дают понятный результат `lolzcloud:room-command-result`. Release, новая комната и замена документа отменяют обе стадии. Успех не подразумевает, что iOS будет исполнять JavaScript при полной приостановке приложения: нативного HTTP-контроллера комнаты здесь нет.

Комнатные команды и их результаты пытаются пройти в готовый доверенный WK-документ и в background: работающий звук WebKit может оставлять его исполняемым. Остальные события сохраняют прежнее ожидание foreground. Это исправляет гарантированную задержку до foreground в первом кандидате; состояние приложения не отменяет проверку владельца, срока или offline suspension. Доставка при реальной блокировке экрана/системной приостановке на физическом устройстве не доказана: чистые тесты проверяют политику active/background, hosted-тест — настоящий bridge при исполняемом WebKit.

Release принимается только от текущих room/document/epoch. Выход и новый document handshake не возобновляют старую сольную музыку; это разрешает только явное solo play/resume. WK `didCommit` и завершение web-content process удаляют владельца прежнего документа. Изменение requestId, эквалайзера или скорости само по себе владельца не снимает. Reload уже явно выбранного сольного плеера не останавливает его.

Для перехода в нативное «Сохранено» оболочка сначала постоянно запрещает WebKit media, дожидается pause, проверяет поколение/клиента захваченного владельца и загружает пустой документ. Старые bridge-сообщения в этом режиме игнорируются. Один pause недостаточен: таймер комнаты мог бы запустить звук снова. Возврат снимает запрет только после удаления старого документа, затем загружает свежий `/app/` без autoplay. Это использует [setAllMediaPlaybackSuspended](https://developer.apple.com/documentation/webkit/wkwebview/setallmediaplaybacksuspended(_:completionhandler:)) и [pauseAllMediaPlayback](https://developer.apple.com/documentation/webkit/wkwebview/pauseallmediaplayback(completionhandler:)), доступные с iOS 15 при deployment target 16.4.

В нативном офлайн-экране есть позиция/длительность, seek, предыдущий/следующий трек, повтор и перемешивание. Очередь использует общий QueuePolicy и приватные проверенные файлы. Полный офлайн-эквалайзер и редактор/провайдеры текста песен в этом экране остаются отдельной работой.

Импорт читает настоящие AVAsset commonMetadata title/artist после проверки аудио. Чтение асинхронно; до 64 metadata items, до четырёх строк каждого типа, три секунды до отмены загрузки. Artwork/произвольные значения не загружаются. Строки очищаются и ограничиваются; при отсутствии тегов используется имя файла и «Локальная музыка». Результат сохраняется обычной атомарной транзакцией приватного index.json. Правила security-scoped copy, квоты и проверки длительности сохраняются.

Новые hosted-тесты добавлены к 17 прежним без изменения их порогов: настоящий MP3 с ID3 title/artist и восстановлением индекса; реальный AVPlayer handoff/маршрутизатор команд/двухфазный ACK; подключённый WKWebView с явно объявленным HTMLAudio fixture, настоящими сообщениями WK, reload и suspension → offline private-file playback/seek/Next/Previous/repeat → возврат без autoplay. Это не тест личного входа, провайдера комнаты, физического Control Center или фонового исполнения на физическом iPhone. Успешный запуск этих трёх тестов Apple SDK пока не заявлен.
