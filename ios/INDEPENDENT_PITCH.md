# Независимая высота тона — iOS 0.1.5 / build 6

Исходники `f7a58a94841f7709388ad003ea40f092f0625d79` прошли Apple SDK 26.2/Xcode 26.3, 84 policy-теста и по 17 настоящих hosted XCTest на iPhone/iPad Simulator. [Отчёт](verification-0.1.5.json) содержит реальные PCM-измерения, историю двух первых неуспешных прогонов и ограничения. Артефакты подготовлены для публикации координатором; старый выпуск 0.1.4 и его история сохранены. Device IPA требует собственной подписи Apple.

`AudioEffectsSettings.pitch` задаёт отношение частот `0.5…2`, по умолчанию `1`. Оно действует независимо от `enabled`: этот флаг включает эквалайзер, предусиление, реверберацию, эхо и нормализацию. Изменение тона не включает сохранённый эквалайзер, не запускает паузу, не выбирает песню и не меняет transport request/generation.

В общем интерфейсе сохраняется желаемое отношение частот. При `preservesPitch=true` оно передаётся как независимый `pitch`; при `false` интерфейс передаёт эффективный `pitch=1`, оставляя AVPlayer в прежнем режиме varispeed. Нативный плеер сохраняет принятую эффективную конфигурацию; желаемое значение общего профиля хранит веб-интерфейс. Это отдельный скаляр высоты тона, а не прежний checkbox выбора `.spectral`/`.varispeed`.

## Совместимость протокола

Сообщение возможностей оставляет `effectsSchema:2` для опубликованного App22/SW7 и добавляет `maxEffectsSchema:3, independentPitch:1`. Новый интерфейс договаривается о schema3 по двум дополнительным полям. Старый интерфейс продолжает отправлять прежние три или шесть полей.

Принятые формы строго ограничены:

- schema1: `enabled, gains, preampDb`;
- schema2: дополнительно `reverb, echo, normalization`;
- schema3: дополнительно `pitch`.

Старые формы явно означают `pitch=1`. Неизвестные поля, неполные формы, boolean вместо числа, NaN/Infinity и выход за пределы отклоняются. Старые сохранённые настройки декодируются с `pitch=1`.

```json
{
  "action": "effects",
  "clientId": "<current lowercase UUID>",
  "requestId": 1,
  "revision": 2,
  "config": {
    "enabled": false,
    "gains": [0, 0, 0, 0, 0],
    "preampDb": 0,
    "reverb": 0,
    "echo": 0,
    "normalization": false,
    "pitch": 1.5
  }
}
```

ACK содержит **ровно** принятую форму `config` и `effectsSchema:1|2|3`; дополнительные поля находятся снаружи `config`. Сохраняются собственная revision эффектов, последний явно принятый client/request и защита от устаревших конфигураций. `capabilities.pitch` становится true только для schema3 после поддерживаемого подготовленного C-процессора, положительного числа реальных кадров и совпадения применённой revision/ratio. Отдельно доступны `pitchLatencyFrames` и `pitchProcessedFrames`. До реальной обработки конфигурация остаётся pending; AVPlayer может обработать prefetched PCM даже в паузе и честно подтвердить такую ревизию. ACK не запускает звук; интерфейс не должен стирать желаемое значение или включать воспроизведение ради подтверждения.

## Настоящий PCM-путь

`PitchCore.c` реализует собственный потоковый STFT с radix-2 FFT, Hann-окном и перекрытием 8. При 44.1/48 кГц размер FFT — 2048, шаг — 256. Соседние спектральные области переносятся вместе с пиком и сохраняют относительные фазы каналов. Простое независимое перемещение бинов было отвергнуто из-за потери громкости; в принятом варианте тесты проверяют и частоту, и RMS, и спектральную амплитуду нужного тона.

Размер FFT подбирается при подготовке, от 512 до 16384 для поддерживаемых 8–384 кГц. Все кольца, FFT-таблицы, выходные буферы и состояние выделяются при prepare. Render не выделяет/освобождает память, не использует блокировки и не вызывает Swift. Stereo использует общую фазовую шкалу. Нечисловой PCM очищается; недопустимые спектральные частоты отбрасываются, а активный pitch проходит через связанный стереолимитер. При pitch1 и выключенных эффектах сохраняется точный сухой сигнал.

У STFT есть задержка N кадров. Поэтому `PCMStream.c` реализует отдельную ограниченную машину потока: предварительно получает N кадров, отбрасывает начальную задержку, а перед EOF дополняет процессор нулями и возвращает хвост **внутри исходного числа выходных кадров**. При discontinuity старое состояние очищается. Это не смена AVPlayer, очереди, timebase, remote commands или фонового audio session. Новая конфигурация тона плавно возвращается к сухому сигналу, подготавливает новый спектр и снова вводит обработку; время трека не перематывается.

Такое поглощение задержки требуется [контрактом Apple process callback](https://developer.apple.com/documentation/mediatoolbox/mtaudioprocessingtapprocesscallback). [EndOfStream](https://developer.apple.com/documentation/mediatoolbox/kmtaudioprocessingtapflag_endofstream) передаётся после завершения обработки. Само название [post-effects tap](https://developer.apple.com/library/archive/qa/qa1783/_index.html) не доказывает положение относительно глобального time-pitch AVPlayer: это отдельно должны подтвердить настоящие hosted PCM-тесты.

## Проверки и границы

Linux Foundation/C и AddressSanitizer проверяют строгую schema3, миграцию, 24 сочетания тонов/ratio, RMS в пределах ±3 дБ, подавление исходного тона, stereo coherence, конечность, limiter, reset, smoothing и exact timeline. Короткие потоки в 1, 123, 2048, 8195 и 48123 кадров сохраняют первый/последний отсчёт и полную длину. Отдельный C probe контролирует отсутствие malloc/calloc/realloc/free внутри render. У Swift AddressSanitizer LeakSanitizer выключен из-за среды XCTest; это явно не проверка отсутствия всех Swift-утечек.

В Apple hosted-набор добавлены три теста; все прежние 14 также прошли. Реальный AVPlayer PCM измерен для локального WAV и кешированного настоящего MP3: темп 0.75/1.5 с pitch 0.5/1.25/2 и baseline, по 14 наблюдений на каждом Simulator. Максимальная относительная ошибка частоты — 0.367%, RMS относительно baseline — 0.9347–1.0. Проверены продвижение/длительность, выключенный EQ, pending prepare, пауза, persistence, seek, duplicate queue/EOF и начальный/конечный аудиофрагмент.

Измеряется полное прежнее окно 200–500 мс после начала именно входного сигнала с теми же допусками 4%/RMS. AVPlayer добавлял тишину до входного сигнала: реальные начальный/конечный маркеры в bins 12/212 совпали на входе и выходе, при 2 секундах между ними. Изменён только origin измерительного fixture; output-окна не подбираются по ожидаемой частоте.

Физические телефоны, акустический выход, Bluetooth/AirPlay, системные звонки, все кодеки и субъективное качество сложного музыкального материала не проверены. Изменение высоты не обещает сохранение формант. Кешированный MP3 в тесте — seeded cache, а не проверка загрузки HTTPS или личного аккаунта.
